# 多知识库联合检索测试验收

## 测试准备

后端已启动，Alembic 迁移已跑完。同一 tenant 下准备两个知识库，各自上传不同主题的文档，确保两库内容有明显区别：

- `kb_ecommerce`：上传电商规则类文档（退款、满减等）
- `kb_customer_service`：上传客服流程类文档（工单、会员补偿等）

另准备一个不同 tenant 的库 ID，用于测试隔离。

## 单库向后兼容测试

这条必须先验，确认旧调用方式零破坏。

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/retrieve \
  -H "Authorization: Bearer rk_live_你的key" \
  -H "Content-Type: application/json" \
  -d '{
    "kb_id": "<kb_ecommerce>",
    "user_id": "test",
    "query": "退款时限",
    "profile": "balanced"
  }'
```

预期：行为与改前完全一致，`retrieved_chunks` 每条带 `kb_id`，值均为 `kb_ecommerce`，`metadata.retrieval.multi_kb` 为 false 或不存在。

## 多库并行召回测试

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/retrieve \
  -H "Authorization: Bearer rk_live_你的key" \
  -H "Content-Type: application/json" \
  -d '{
    "kb_ids": ["<kb_ecommerce>", "<kb_customer_service>"],
    "user_id": "test",
    "query": "退款时会员补偿怎么算",
    "profile": "balanced",
    "top_k": 5
  }'
```

预期：

1. `code` 为 0，`data.kb_ids` 含两个 id
2. `retrieved_chunks` 中两个库都有机会出现（取决于内容相关性）
3. 每条 chunk 有 `kb_id` 和 `kb_name` 字段
4. `metadata.retrieval.multi_kb` 为 true，`fusion` 为 `rrf`，`kb_count` 为 2

## RRF 融合效果验证

目视对比融合结果与单库召回的差异，验证 RRF 能均衡覆盖多库。

1. 分别用单库跑两次 retrieve，记录各自 Top 5
2. 再跑 `kb_ids` 双库，看 Top 5 是否兼顾了两库的相关结果
3. 预期：双库结果不会让某一个库的 chunk 全部占满前排，另一库完全缺席

## 检索日志验证

发起一次双库 retrieve 后，查 `retrieval_logs` 表：

```sql
SELECT kb_ids, trace_id, latency_ms
FROM retrieval_logs
ORDER BY created_at DESC
LIMIT 1;
```

预期：`kb_ids` JSONB 字段含两个库的 ID；`trace_id` 非空（Langfuse 启用时）。

## 离线测评测试

### 1. 跑跨库 eval dataset

```bash
python scripts/run_retrieval_eval.py \
  --dataset eval/datasets/multi_kb_cases.json \
  --api-key rk_live_你的key \
  --profile balanced \
  --output eval/reports/multi_kb_balanced.json
```

预期：report 生成，跨库 case 的 `context_recall` 合理，report 里每条 case 有 `multi_kb: true` 标记。

### 2. 单库 eval 回归

```bash
python scripts/run_retrieval_eval.py \
  --dataset eval/datasets/ecommerce_retrieval.json \
  --api-key rk_live_你的key \
  --profile balanced \
  --output eval/reports/regression_balanced.json
```

预期：单库 case 的两项指标与优化十三前的 baseline 无明显下降，确认单库路径未破坏。

### 3. Langfuse 导出包含 kb_ids

```bash
python scripts/export_eval_cases_from_langfuse.py \
  --max-score 3 \
  --days 7 \
  --output eval/datasets/imported_multi_kb.json
```

预期：多库 retrieve 产生的低分反馈，导出 case 里 `kb_ids` 字段为列表而非单值。
