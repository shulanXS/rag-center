# 03 - 调试台与离线测评适配

01、02 后端已支持 `kb_ids` 与跨库 RRF。业务方和教程演示还需要 **调试台能选多个库**，离线测评也要能 **批量跑多库 retrieve**，否则优化十三只能 curl 验证，难以融入优化十的闭环。

本篇改 **前端检索页 + eval 脚本 + 文档**，后端若无遗漏则不动核心逻辑。

## 调试台要怎么改

### 检索页 `/retrieve`

**检索范围区：**

- 原：单个 `kb_id` 输入框
- 新：从 `GET /knowledge-bases/tree` 拉当前 tenant 的知识库列表，**Checkbox 多选**

**提交：**

- 选中 1 个库 → 可只传 `kb_id`（兼容）或 `kb_ids: [one]`
- 选中多个 → 传 `kb_ids: [...]`

**结果展示：**

- 每个 chunk Card 增加 Badge：`kb_name` 或 `kb_id` 前 8 位
- 运行摘要区只读展示：`metadata.retrieval.multi_kb`、`kb_count`、`fusion`

**plan 提示：**

- 若 `GET /auth/me` 或 retrieve 错误 20013，提示「当前套餐最多支持 N 个库联合检索」
- 可选：PlanBadge 旁增加说明 link 到 tenant-onboarding

### 列表页跳转

「去检索」仍带单个 `kb_id`；到检索页后该库 **默认勾选**。用户可再勾选其他库。

URL 可选：`/retrieve?kb_id=xxx` 不变；多库不写 URL，只在页内选择。

## 离线测评怎么适配

### dataset 格式扩展

`eval/datasets/*.json` 的 case 支持：

```json
{
  "question": "退款时会员等级有什么补偿？",
  "kb_ids": ["<ecommerce_kb_id>", "<customer_service_kb_id>"],
  "ground_truth": "……关键句……"
}
```

兼容：仅有 `kb_id` 的 case 仍按单库跑。

### run_retrieval_eval.py

- 读 case 时：`kb_ids = case.get("kb_ids") or [case["kb_id"]]`
- 请求 body 传 `kb_ids`
- report 里记录 `multi_kb: true/false`

### 新增跨库 golden case

在 `eval/datasets/` 增加或合并 2～3 条 **必须跨库才能答全** 的 case，例如：

| question | kb_ids | ground_truth 要点 |
|----------|--------|-------------------|
| 退款时限和会员补偿标准 | ecommerce + customer_service | 各库各一句 |

跑通 RAGAS 后，与单库分别 retrieve 对比 recall——**多库应不低于单库最优**，理想情况明显更高。

## Langfuse 与反馈

优化十已支持 feedback 关联 trace。多库 retrieve 的 trace metadata 含 `kb_ids` 后，导出 eval case 脚本 `export_eval_cases_from_langfuse.py` 应：

- 优先读 `metadata.kb_ids`
- 回退 `metadata.kb_id`

无需大改，确认字段名一致即可。

## 做完怎么验

### 1. 调试台多库检索

1. 打开 `/retrieve`，勾选 ecommerce + customer_service
2. 输入跨域 query，profile `balanced`
3. 预期：结果来自两个库，Badge 可区分；运行摘要有 `multi_kb`

### 2. 离线测评

```bash
python scripts/run_retrieval_eval.py \
  --dataset eval/datasets/multi_kb_cases.json \
  --api-key rk_live_你的key \
  --profile balanced \
  --output eval/reports/multi_kb_balanced.json
```

预期：report 生成成功；跨库 case 的 `context_recall` 合理。

### 3. 单库回归

对原 `ecommerce_retrieval.json` 再跑一遍，分数与优化十三前同一 baseline 相比 **不应明显下降**（单库路径未破坏）。
