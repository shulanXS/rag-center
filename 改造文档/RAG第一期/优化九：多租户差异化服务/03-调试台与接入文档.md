# 03 - 调试台与接入文档

01 有 plan，02 有配额 enforcement 和 retrieve `profile`。这一步让调试台**能选四档、能看套餐**，并补一份简短的接入说明，让新租户不看源码也能上手。

## 调试台改什么

### 列表页 `/knowledge-bases`

顶栏在现有租户名称 / ID 旁增加 **plan Badge**：免费 / 标准 / 专业，对应 `free` / `standard` / `pro`。

可选：旁边加一行「今日检索 128 / 5000」，数据来自 `/auth/me` 的 `usage` / `limits`。

检索策略不在这里展示——profile 在检索页选，不挂在租户档案上。

### 检索页 `/retrieve`（本篇重点）

顶部增加四档 **检索 profile** 单选，可以用 Tab 或 Radio 实现：

| UI 文案 | 传参 `profile` | 说明 |
|---------|----------------|------|
| 追求速度 | `speed` | vector，最快 |
| 均衡 | `balanced` | hybrid，默认 |
| 追求质量 | `quality` | hybrid + rerank + rewrite；**standard/free 置灰** |
| 自定义 | `custom` | 展开下方高级参数 |

几个交互细节：

1. 进入页面调 `/auth/me`，按 plan 置灰不可选项。free 仅能选「追求速度」；standard 无「追求质量」。
2. 选前三项时折叠高级参数（由后端 preset 展开）
3. 选「自定义」时展开现有高级参数；仍受 plan 置灰，比如 standard 的 rerank 开关禁用
4. 每次检索必带 `profile`
5. 置灰项加 Tooltip：「当前为标准套餐，不支持追求质量。请升级专业套餐，或选用均衡 / 自定义。」
6. 可选：结果区折叠展示 `metadata.tenant_policy`

### 上传页 `/`

超配额（20014）时展示后端 `msg`，不要空白失败。

### GET /auth/me 扩展

```json
{
  "tenant_id": "tenant_a",
  "tenant_name": "租户 A",
  "plan": "standard",
  "features": {
    "allowed_profiles": ["speed", "balanced", "custom"],
    "hybrid_allowed": true,
    "rerank_allowed": false,
    "query_rewrite_allowed": false
  },
  "limits": {
    "retrieve_qps": 10,
    "retrieve_daily": 5000,
    "max_kb": 5,
    "max_documents_per_kb": 200,
    "max_processing_documents": 2
  },
  "usage": {
    "kb_count": 3,
    "retrieve_daily": 128
  }
}
```

无 `profile` 字段——检索策略不属于租户档案。

## 接入文档

新建 `docs/tenant-onboarding.md`（README 加链接），建议结构：

1. **定位**：检索中台，retrieve 返回 chunk，生成在业务方
2. **开通**：`create_tenant` → `create_api_key` → 请求带 `Authorization: Bearer KEY`
3. **plan 三档对照表**，与 01 表格一致
4. **retrieve profile 四档说明** + curl 示例（带 `profile` 字段）
5. **plan 与 profile 的关系**：plan 管上限；profile 管本次策略；不传 profile 默认 balanced
6. **错误码**：20010 / 20013 / 20014 / 20005
7. **旧租户**：迁移后为 standard；升档用 `update_tenant_plan.py`

## 做完怎么验

前置：01、02 已完成；Redis + 后端 + Celery Worker 运行中；`frontend/.env` 配好各 tenant 的 `API_KEY`；前端 `npm run dev` 已启动。

建议准备三个 Key 分别对应 free / standard / pro（见 02 验收的建 tenant 步骤）。

### 1. auth/me 返回 plan 与配额

```bash
curl -s http://127.0.0.1:8000/api/v1/auth/me \
  -H "Authorization: Bearer KEY_STD"
```

预期：`code` 为 0，`data` 含：

- `plan`: `"standard"`
- `features.allowed_profiles`: 含 `speed`、`balanced`、`custom`，**不含** `quality`
- `features.rerank_allowed`: `false`
- `limits.max_kb`: `5`
- `usage.kb_count`: 当前库数

再用 free 的 Key 测一次，预期 `plan: "free"`，`allowed_profiles` 仅含 `speed`。

### 2. 列表页 plan Badge

1. 浏览器打开 `/knowledge-bases`，`.env` 使用 **standard** 的 Key
2. 预期：顶栏可见 **标准** Badge；可选：今日检索用量
3. 换成 **pro** 的 Key，重启 dev server，刷新
4. 预期：Badge 变为 **专业**

不应出现租户级 profile Badge。

### 3. 检索页 — pro 租户

1. 使用 **pro** Key，打开 `/retrieve`
2. 预期：四档均可选
3. 选 **追求质量**，填 `kb_id` 与 query，点检索
4. 预期：成功返回 chunk；Network 请求体含 `"profile": "quality"`

### 4. 检索页 — standard 租户

1. 使用 **standard** Key，打开 `/retrieve`
2. 预期：**追求质量** 置灰；hover 有升级提示
3. 选 **均衡**，检索成功
4. 选 **自定义**：rerank / query rewrite 开关应置灰
5. Network：请求含 `"profile": "balanced"` 或 `"custom"`，且无 `rerank_options.enabled: true`

### 5. 检索页 — free 租户

1. 使用 **free** Key，打开 `/retrieve`
2. 预期：仅 **追求速度** 可选；均衡 / 质量 / 自定义置灰
3. 检索成功；`profile` 为 `speed`

### 6. 上传页配额错误

1. free 租户已有 1 个库，在上传页再**创建知识库**
2. 预期：页面展示后端返回的 20014 文案，比如「免费档仅支持 1 个知识库」，不要空白失败

### 7. 接入文档 walkthrough

1. 打开 `docs/tenant-onboarding.md`
2. 按文档「开通流程」用脚本建 tenant、发 Key
3. 按 curl 示例带 `profile` 字段调 retrieve
4. 预期：不查源码也能完成接入

### 8. 导航与鉴权（回归）

1. 三页顶栏链接正常
2. 将 `API_KEY` 改为错误值，刷新列表页
3. 预期：提示 20010 未授权，与优化六行为一致
