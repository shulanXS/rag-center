# 设计调试台套餐适配与接入文档提示词

点击此处可复制本篇提示词

后端套餐和配额已全部就绪，这篇只做两件事：把 plan 和 profile 能力接到调试台页面，再补一篇接入文档让新租户不看源码也能上手。改动范围很小，重心在交互设计。

## 使用场景

这份提示词依赖后端套餐与配额（01+02）已完成。此时 `/auth/me` 已返回 plan、features、limits、usage，retrieve 接口支持 `profile` 参数并会按 plan 进行校验。

前端目前缺三件事：

- 检索页没有 profile 选择器，一直在用后端默认的 balanced
- 列表页看不到当前租户是哪个套餐
- 上传页超配额时失败没有提示

本篇只改前端，不新增后端逻辑。

### 一、功能目标

- 检索页增加四档 profile 单选，按 plan 置灰不可用档位
- 列表页顶栏展示当前租户套餐 badge
- 上传页捕获 20014 并展示友好错误
- 扩展 types 和 services 对齐新字段
- 新增 `docs/tenant-onboarding.md` 接入文档

### 二、/auth/me 类型对齐

后端已扩展，前端补齐对应 types：

```typescript
// types/api.ts
interface AuthMeData {
  tenant_id: string
  tenant_name: string
  plan: "free" | "standard" | "pro"
  features: {
    allowed_profiles: string[]
    hybrid_allowed: boolean
    rerank_allowed: boolean
    query_rewrite_allowed: boolean
  }
  limits: {
    retrieve_qps: number
    retrieve_daily: number
    max_kb: number
    max_documents_per_kb: number
    max_processing_documents: number
  }
  usage: {
    kb_count: number
    retrieve_daily_count: number
  }
}
```

`RetrieveRequest` 增加 `profile?: "speed" | "balanced" | "quality" | "custom"`，`ragService.retrieve` 把 profile 带入请求体。

### 三、列表页 plan badge

列表页顶栏在租户名称旁增加套餐 badge，调用现有 `fetchAuthMe` 取数据：

| plan 值 | badge 文案 | 颜色 |
|---|---|---|
| free | 免费 | 灰色 |
| standard | 标准 | 蓝色 |
| pro | 专业 | 紫色或金色 |

可选：badge 旁展示「今日检索 128 / 5000」，数据来自 `usage.retrieve_daily_count` 和 `limits.retrieve_daily`。

不展示租户级 profile，检索策略由每次请求决定。

### 四、检索页 profile 选择器

检索配置区顶部增加四档单选，可用 Tab 或 Radio 实现：

| UI 文案 | 传参 profile | 说明 |
|---|---|---|
| 追求速度 | speed | vector 检索，最快 |
| 均衡 | balanced | hybrid，默认 |
| 追求质量 | quality | hybrid + rerank + rewrite |
| 自定义 | custom | 展开下方高级参数 |

**按 plan 置灰规则：**

进入页面调 `fetchAuthMe`，按 `features.allowed_profiles` 决定哪些档位可选：

- free：仅 speed 可选，其余三档置灰
- standard：quality 置灰，其余可选
- pro：四档全开

置灰项加 `HelpTooltip`，文案说明原因和升级路径，比如「当前为标准套餐，不支持追求质量。如需使用请升级专业套餐。」

**选 speed / balanced / quality 时：** 折叠高级参数区，这三档由后端 preset 展开，前端不需要传具体 options，只传 `profile`。

**选 custom 时：** 展开现有高级参数，供手动配置 mode、top_k、rerank、rewrite 等。custom 下各参数仍受 plan 约束：

- `features.rerank_allowed=false` 时，rerank 开关置灰
- `features.query_rewrite_allowed=false` 时，query rewrite 勾选框置灰
- `features.hybrid_allowed=false` 时，mode 选项仅显示 vector 和 bm25

每次检索必须传 `profile`，禁用项不出现在请求体里。

可选：结果区折叠展示 `metadata.tenant_policy`，供调试时对照生效参数。

### 五、上传页配额错误处理

创建知识库和上传文档时，捕获后端返回的 20014 错误并展示 `msg` 字段内容，比如「免费档仅支持 1 个知识库，请升级套餐」。不要空白失败或只显示「请求失败」。

### 七、接入文档

新建 `docs/tenant-onboarding.md`，README 加链接。文档供新租户接入时参考，不看源码也能完成配置。

建议结构：

1. **定位**：RAG 检索中台，retrieve 返回 chunk，答案生成在业务方自行处理
2. **开通步骤**：`create_tenant` → `create_api_key` → 请求头带 `Authorization: Bearer KEY`
3. **plan 三档对照表**，与代码里一致
4. **retrieve profile 四档说明** + curl 示例，每条带 `profile` 字段
5. **plan 与 profile 的关系**：plan 管能用什么，profile 管这次怎么跑，不传 profile 默认 balanced
6. **词表配置**：各 plan 都能用，用 `update_kb_settings.py` 脚本维护
7. **常见错误码**：20010（未授权）/ 20013（功能超 plan）/ 20014（配额超限）/ 20005（QPS 限流）
8. **旧租户说明**：迁移后默认 standard，升档用 `update_tenant_plan.py`

### 八、验收标准

- pro 租户：四档全部可选，选追求质量后检索成功，Network 请求体含 `profile: "quality"`
- standard 租户：追求质量置灰，hover 有升级提示；均衡可用；自定义下 rerank 开关置灰
- free 租户：仅追求速度可选，其余置灰
- 列表页顶栏出现对应套餐 badge
- 上传页超配额时展示后端返回的中文错误文案，不空白失败
- `docs/tenant-onboarding.md` 按文档步骤能完成新租户接入
