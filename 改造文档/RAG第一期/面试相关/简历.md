# RAG 检索中台（rag-center）

## 项目介绍

企业级 RAG 检索中台，为多业务线提供知识库管理、文档异步索引与多策略检索的统一 API；职责边界限于证据片段召回与结构化返回，答案生成、Prompt 编排与前端交互由上游应用承接。具备多租户隔离、API Key 鉴权、三档商业套餐，以及 QPS、日检索量、知识库规模等配额管控能力。

技术栈为 FastAPI、PostgreSQL + pgvector、Elasticsearch、Celery + Redis，配套 React 调试台。检索侧覆盖查询改写、词表扩展、向量与 BM25 双路召回、RRF 融合、多库联查与 LLM 精排；入库侧支持 Markdown 结构化切块及 Word、PDF 多格式解析；观测侧贯通 Langfuse 链路追踪、检索审计日志、用户反馈与 RAGAS 离线评测，支撑检索质量持续迭代。

---

## 个人职责

- **整体架构与模块划分**：主导中台分层设计，从 API、Service、Repository 到 Provider 逐层拆分，划分知识管理、异步索引、检索编排、多租户配额、效果评估等模块，完成技术选型与统一接口规范。
- **检索主链路落地**：打通从套餐校验、问题处理、双路召回到 RRF 融合、可选精排、结构化返回的完整链路，支持速度、均衡、质量、自定义四档检索策略，并与租户套餐能力做双层约束。
- **索引与文档引擎**：设计 Celery 异步索引流水线，覆盖解析、结构化切块、批量向量化、向量库与搜索引擎双写；实现文档状态机、失败重试、清库重索引和全库重建脚本，并接入 Word、PDF 解析，统一产出可供切块的正文。
- **多租户与商业化配额**：实现 API Key 鉴权与哈希存储、租户级数据隔离、三档套餐的功能开关，以及 QPS、日检索量、知识库数量、并发索引数等配额限制，超限返回明确错误码。
- **可观测与效果闭环**：建设检索审计日志、Langfuse 链路追踪、用户反馈评分，并集成 RAGAS 离线评测，支撑线上问题定位、低分 case 沉淀和调参前后对比。
- **全栈调试台**：独立开发 React + TypeScript 前端，覆盖建库、多格式上传、文档状态、检索调试、策略与多库切换、套餐用量展示和结果反馈，降低业务接入成本。

## 难点与亮点

- **中台定位与多租户分级服务**：检索与生成职责分离，API Key 鉴权 + 三档 Plan 锁定长期功能开关与资源配额，单次请求通过 Profile 独立选择速度 / 均衡 / 质量策略，租户数据全链路隔离，超限明确报错，避免各业务重复建设向量库与搜索引擎，也避免在账号层反复改配置才能切换检索策略。
- **检索全链路优化**：将单纯向量 TopK 检索升级为完整检索链路：用户问题 → LLM 语义改写 → 同义词词表扩展 → pgvector 向量路 + Elasticsearch BM25 路并行召回 → RRF 融合 → 跨库二次融合 → 可选 LLM 精排（speed / balanced / quality 按套餐分档）。固定电商知识库评测集上，召回率由约 61% 提升至 76%。
- **结构化入库夯实检索底座**：Word / PDF / Markdown 多格式经 DocumentParser 插件统一解析为 Markdown 正文，再按标题层级与表格边界结构化切块，解析层与切块层解耦，双写入库并支持失败回滚与 purge 重索引；全库 reindex 后同一评测集召回率由约 58% 提升至 71%，准确率由约 54% 提升至 67%，为后续改写、混合召回与精排提供更完整的片段输入。
- **检索效果可度量、可回归**：检索日志落库、Langfuse 分阶段耗时追踪、用户反馈沉淀低分 case，配合 RAGAS 离线评测；综合词表、切块与 profile 调优后，固定评测集准确率由约 59% 提升至 76%，召回率由约 55% 提升至 82%，调参前后可对比、可回归，避免上线后不知好坏、迭代无依据。
- **核心链路多层降级韧性**：hybrid 模式下单路召回失败自动退化为另一路；LLM 改写、精排、Langfuse 上报超时或异常均旁路降级，保证模型或 ES 故障时检索主链路仍可返回可用结果，避免整单失败。
- **六类 Provider 可插拔工程架构**：Embedding、向量库、搜索引擎、LLM、Rerank、文档解析统一抽象，工厂 + 环境变量切换实现；分段错误码区分未授权、功能超限、配额用尽与限流，换模型或存储后端不改核心业务编排，Noop Provider 表达「套餐不支持」而不污染业务分支。
