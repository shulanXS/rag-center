# 知识库生命周期管理测试验收

## 测试准备

PostgreSQL、Elasticsearch、Redis 均已启动，`.env` 配好 Embedding API，`AUTH_ENABLED=true`。需要同时跑两个进程：

终端一启动后端：

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

终端二启动 Worker：

```bash
celery -A app.celery_app worker --loglevel=info
```

确认 Redis 可连：

```bash
redis-cli -p 6379 ping
# 预期：PONG
```

跑迁移：

```bash
alembic upgrade head
```

## 异步索引测试

### 1. upload 应立即返回 PROCESSING

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/documents/upload \
  -H "Authorization: Bearer rk_live_REDACTED" \
  -H "Content-Type: application/json" \
  -d '{
    "kb_id": "70d6a771-d475-41aa-a309-3069e8e2ec33",
    "title": "异步索引测试",
    "content": "这是一段用于验证异步索引的测试内容，Worker 会在后台完成索引工作。"
  }'
```

预期：1 秒内返回，`data.status` 为 3（PROCESSING），`chunk_count` 为 0。记下 `document_id`。

### 2. 轮询状态直到 SUCCESS

```bash
curl -s http://127.0.0.1:8000/api/v1/documents/你的document_id \
  -H "Authorization: Bearer rk_live_你的key"
```

等 Worker 跑完后再调，预期 `status` 变为 1（SUCCESS），`chunk_count` 大于 0，`error_message` 为 null。

### 3. 检索验证索引生效

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/retrieve \
  -H "Authorization: Bearer rk_live_你的key" \
  -H "Content-Type: application/json" \
  -d '{"kb_id":"你的kb_id","user_id":"test_user","query":"异步索引测试"}'
```

预期：能召回刚上传文档的 chunk。

### 4. 索引失败场景

停掉 Elasticsearch，再 upload 一份新文档，等 Worker 重试完：

```bash
docker compose stop elasticsearch
```

查状态：

```bash
curl -s http://127.0.0.1:8000/api/v1/documents/新document_id \
  -H "Authorization: Bearer rk_live_REDACTED"
```

预期：`status` 为 2（FAILED），`error_message` 非空。测完恢复：

```bash
docker compose start elasticsearch
```

## 知识库运维接口测试

### 1. GET 知识库详情

```bash
curl -s http://127.0.0.1:8000/api/v1/knowledge-bases/KB_ID \
  -H "Authorization: Bearer KEY"
```

预期：`code` 为 0，返回 name、description、settings、document_count。

### 2. PATCH 更新 settings，词表应即时生效

```bash
curl -s -X PATCH http://127.0.0.1:8000/api/v1/knowledge-bases/KB_ID \
  -H "Authorization: Bearer KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "settings": {
      "synonyms": [
        { "terms": ["测试词"], "expand": ["扩展词A", "扩展词B"] }
      ]
    }
  }'
```

预期：`code` 为 0。用含「测试词」的 query retrieve，验证 `metadata.query_processing.synonym_applied` 为 true。

### 3. PATCH 传非法 settings，应返回错误

```bash
-d '{"settings": {"synonyms": [{"terms": [], "expand": ["x"]}]}}'
```

预期：`code` 非 0，提示参数错误。

### 4. DELETE 知识库，下属 chunk 应一并清除

```bash
curl -s -X DELETE http://127.0.0.1:8000/api/v1/knowledge-bases/KB_ID \
  -H "Authorization: Bearer KEY"
```

预期：`code` 为 0。tree 无该库；以该 kb_id 发起 retrieve 返回知识库不存在或无结果。

## 文档运维接口测试

### 1. DELETE 文档，chunk 应一并清除

```bash
curl -s -X DELETE http://127.0.0.1:8000/api/v1/documents/DOC_ID \
  -H "Authorization: Bearer KEY"
```

预期：`code` 为 0；tree 无该文档；针对该文档内容的 retrieve 不再命中。

### 2. PROCESSING 时 DELETE 应被拒绝

upload 后立刻发 DELETE，Worker 还未跑完时：

预期：`code` 非 0，提示文档正在索引中。

### 3. FAILED 文档 reindex，最终应 SUCCESS

制造 FAILED 文档（参考上方索引失败场景），恢复 ES 后：

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/documents/FAILED_DOC_ID/reindex \
  -H "Authorization: Bearer KEY"
```

预期：返回 status=PROCESSING，最终 Worker 跑完变 SUCCESS。

### 4. SUCCESS 文档 reindex 应被拒绝

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/documents/SUCCESS_DOC_ID/reindex \
  -H "Authorization: Bearer KEY"
```

预期：`code` 非 0，已成功的文档不允许重试。

### 5. 库内有 PROCESSING 文档时，DELETE 知识库应被拒绝

upload 后立刻尝试删库（Worker 未跑完）：

预期：`code` 非 0，提示库内有文档正在索引中。

## 调试台测试

### 1. 上传体验

1. 打开上传页，选 kb，上传一个 `.md` 文件
2. 预期：很快提示「已提交，正在后台索引」，不必等秒
3. 打开列表页 `/knowledge-bases`，该文档显示「索引中」badge
4. 等数秒后 badge 自动变「成功」，无需手动刷新（轮询生效）

### 2. 失败与重试

1. 停 ES，上传新文档，等 FAILED
2. 列表页该文档显示「失败」badge 和错误摘要，悬停可看全文
3. 恢复 ES，点「重试」
4. 预期：变「索引中」→「成功」

### 3. 编辑知识库

1. 知识库行点「编辑」，Dialog 打开，字段预填正确
2. 修改名称，settings JSON 里加一组 synonyms，保存
3. tree 中知识库名称更新
4. 检索页用命中词表的 query，验证 synonym_applied 为 true

### 4. 删除文档

1. 对 SUCCESS 文档点「删除」，出现二次确认 Dialog
2. 确认后文档从 tree 消失，检索不再命中
3. PROCESSING 文档删除按钮应隐藏或禁用

### 5. 删除知识库

1. 对测试库点「删除」，出现二次确认 Dialog，提示不可恢复
2. 确认后整库从 tree 消失
