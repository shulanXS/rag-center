# 03 - 调试台生命周期运维

01、02 后端已经齐了：upload 异步索引、文档状态可查、知识库 GET/PATCH/DELETE、文档 DELETE/reindex，tree 也会返回 PROCESSING / FAILED / SUCCESS 三种状态。

但调试台还停留在「只能建、只能传、只能看成功的文档」——改库名、删文档、重试失败，都得 curl。这一步把 01、02 的能力**接到前端**，让生命周期在调试台里闭环。

## 要补哪些交互

先捋一下前后端的差距：upload 已经秒回 PROCESSING，但前端还在等成功；tree 已经返回三种状态，但列表页只展示 SUCCESS；知识库的编辑和删除 API 都有，但页面上没有入口。

理想路径是：建库 → 上传（秒回）→ 列表看索引进度 → 失败点重试 → 编辑库名/词表 → 删错文档 → 删废弃库，一页都不必离开。

文档内容要改怎么办？02 没有 PUT 接口，这里也不做正文编辑 UI——在列表页删掉那条文档，回上传页重传新内容就好。

## 列表页 /knowledge-bases 怎么改

### 文档层：三种状态都要看得见

| status | 展示 | 操作 |
|--------|------|------|
| PROCESSING (3) | Badge「索引中」 | 无（或禁用删除） |
| FAILED (2) | Badge「失败」+ `error_message` 摘要 | 「重试」 |
| SUCCESS (1) | Badge「成功」 | 「删除」 |

`error_message` 过长时截断展示，悬停可看全文，用 Tooltip 实现。

### 知识库层：编辑与删除

知识库行增加两个操作入口：

- **编辑**：Dialog 打开，先调 `GET /knowledge-bases/{kb_id}` 预填数据。字段有名称、描述、settings，settings 用 JSON 文本框展示，默认格式化缩进。保存调 `PATCH`；settings JSON 格式错误先在前端提示，别发请求；后端校验失败展示 `msg`。
- **删除**：Confirm Dialog「将删除该库及全部文档，不可恢复」→ `DELETE /knowledge-bases/{kb_id}` → 刷新 tree。

现有的复制 kb_id、去上传、去检索都保留。

### PROCESSING 轮询

当 tree 数据中存在 `status === 3` 的文档时，每 **3 秒**自动 refetch tree，用 TanStack Query 的 `refetchInterval` 实现。全部文档进入终态后停止轮询。轮询期间列表顶部可显示小字「有文档正在索引…」。

不必单独轮询 `GET /documents/{id}`，tree 已含 status，够用且请求数更少。

### 文档行操作

- **删除**（SUCCESS / FAILED）：Confirm → `DELETE /documents/{id}` → refetch；若要换内容，去上传页重新 upload
- **重试**（仅 FAILED）：`POST /documents/{id}/reindex` → refetch → 进入轮询

PROCESSING 时删除按钮隐藏或 disabled。

## 上传页怎么改

01 之后 upload 返回 PROCESSING 就算成功，不必等 Worker 跑完：

- `uploadDocument` 收到响应即算「提交成功」，不再等 SUCCESS
- Toast：「已提交，正在后台索引」
- 可选：结果区加链接「去列表查看进度」→ `/knowledge-bases`

批量上传时，多个文件可同时处于 PROCESSING，列表页轮询统一展示。创建知识库逻辑不变。

## Service / Types 改动

**types/api.ts**：`DocumentTreeItem` 增加 `error_message: string | null`；新增 `KnowledgeBaseDetailData`、`UpdateKnowledgeBaseRequest`。

**knowledgeBaseService.ts**：新增 `fetchDetail(kbId)`、`updateKnowledgeBase(kbId, payload)`、`deleteKnowledgeBase(kbId)`。

**documentService.ts**：新增 `deleteDocument(documentId)`、`reindexDocument(documentId)`。

## 组件建议

- **ConfirmDialog**：删库、删文档复用（shadcn AlertDialog 或现有 Dialog）
- **EditKnowledgeBaseDialog**：名称 Input、描述 Textarea、settings Textarea，用等宽字体
- **StatusBadge**：根据 status 1/2/3 映射颜色，成功绿、失败红、处理中黄或蓝

未授权时 `code: 20010`，继续走现有 `authError` 提示，不必本篇单独做。

本篇只改前端三页（上传、列表、检索页顶栏逻辑不动），不新增后端接口；文档内容在线编辑也不做——改内容就删后重传；settings 仍用 JSON 文本框，不做词表可视化表单。

## 做完怎么验

前置：01 Worker 运行中；02 API 可用；`frontend/.env` 配好 `API_KEY`；前后端均已启动。

### 1. 上传体验

1. 打开上传页 `/`，选 kb，上传一个 `.md` 文件
2. 预期：很快提示「已提交 / 正在索引」，不必等几十秒
3. 点「去列表」或手动打开 `/knowledge-bases`
4. 预期：该文档显示「索引中」Badge
5. 等待数秒（Worker 跑完）
6. 预期：Badge 变为「成功」，无需手动刷新（轮询生效）

### 2. 失败与重试（可选）

1. 停 ES，上传新文档，等 FAILED
2. 列表页该文档显示「失败」和错误摘要
3. 恢复 ES，点「重试」
4. 预期：变「索引中」→「成功」

### 3. 编辑知识库

1. 某知识库行点「编辑」
2. 改名称，settings JSON 里加一组 synonyms
3. 保存后 tree 名称更新
4. 去检索页用命中词表的原话 query
5. 预期：`synonym_applied` 为 true

### 4. 删除文档

1. 对 SUCCESS 文档点「删除」，确认
2. 预期：文档从 tree 消失；检索不再命中
3. 若要换内容：回上传页重新 upload 新文件

### 5. 删除知识库

1. 对测试库点「删除」，确认
2. 预期：整库从 tree 消失

### 6. 批量上传

1. 上传页一次选 3 个文件
2. 列表页预期：短暂内可见多条 PROCESSING，随后逐一 SUCCESS

### 7. 导航与鉴权

1. 三页顶栏链接正常
2. `API_KEY` 改错后操作应提示 20010
