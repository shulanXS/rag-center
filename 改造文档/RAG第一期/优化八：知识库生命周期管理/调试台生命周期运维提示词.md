# 设计调试台生命周期运维提示词

点击此处可复制本篇提示词

后端已经完备：upload 异步秒回、文档状态可查、知识库和文档增删改查都有接口。这篇把这些能力接到前端，让调试台里能完成知识库从创建到废弃的完整流程，不必再开终端 curl。

## 使用场景

这份提示词依赖后端异步索引与运维 API（01+02）已完成。此时 upload 返回的是 PROCESSING，不是 SUCCESS；tree 接口已返回三种状态；知识库和文档的 GET/PATCH/DELETE 接口均可用。

前端目前的状态是：upload 还在等 SUCCESS 才算成功；列表页只展示 SUCCESS 文档；没有编辑和删除的交互入口。

理想操作路径：建库 → 上传（秒回）→ 列表看索引进度 → 失败点重试 → 编辑库名和词表 → 删错文档 → 删废弃库，一页都不必离开。

本篇只改前端，不新增后端接口。

### 一、功能目标

- 上传页适配异步响应，收到 PROCESSING 即提示成功
- 列表页展示三种文档状态，并提供删除和重试操作
- 知识库行增加编辑和删除入口
- 列表页对 PROCESSING 文档自动轮询，无需手动刷新
- 补充 types、services 对齐新接口

### 二、上传页改动

01 之后 upload 返回的是 `status=PROCESSING`，认为提交成功不需要等 Worker 跑完。收到响应即算「提交成功」，Toast 提示「已提交，正在后台索引」，不再等 SUCCESS 才显示完成。

可选在结果区加一个链接「去列表查看进度」，跳转到 `/knowledge-bases`。批量上传时多个文件可同时处于 PROCESSING，列表页轮询统一展示。创建知识库逻辑不变。

### 三、列表页文档行

当前列表页只展示上传成功的文档。改为三种状态都显示，每种状态有对应的视觉标识和操作：

| 状态 | Badge 样式 | 附加信息 | 可用操作 |
|---|---|---|---|
| PROCESSING（3） | 黄色或蓝色「索引中」 | 无 | 删除按钮隐藏或禁用 |
| FAILED（2） | 红色「失败」 | error_message 摘要 | 「重试」 |
| SUCCESS（1） | 绿色「成功」 | 无 | 「删除」 |

`error_message` 过长时截断展示，悬停 Tooltip 看全文。

**删除文档：** SUCCESS 和 FAILED 状态可点「删除」，弹 Confirm 确认后调 DELETE，成功后 refetch tree。文档内容有误时，删除后回上传页重传新内容，没有原地编辑入口。

**重试文档：** 仅 FAILED 状态显示「重试」按钮，点击后调 POST reindex，成功后 refetch tree，该文档随即进入 PROCESSING 状态开始轮询。

### 四、列表页知识库行

知识库行增加两个操作入口，现有的复制 kb_id、去上传、去检索全部保留。

**编辑知识库：** 点击打开 Dialog，先调 `GET /knowledge-bases/{kb_id}` 预填数据。Dialog 包含三个字段：名称 Input、描述 Textarea、settings JSON Textarea（等宽字体展示）。settings 默认格式化缩进，方便阅读。保存前在前端 parse JSON，格式错误直接提示，不发请求。保存调 PATCH，后端校验失败展示返回的 msg。

**删除知识库：** 弹 Confirm Dialog，提示文案「将删除该库及全部文档，不可恢复」，确认后调 DELETE，成功后 refetch tree。

### 五、PROCESSING 轮询

当 tree 数据中存在 `status === 3` 的文档时，列表页自动每 3 秒 refetch 一次 tree，使用 TanStack Query 的 `refetchInterval` 实现。全部文档进入终态（SUCCESS 或 FAILED）后停止轮询，不必一直跑。

轮询期间列表顶部可选展示小字「有文档正在索引…」，让用户感知到当前有后台任务在进行。不必单独轮询 `GET /documents/{id}`，tree 已含 status，请求数更少。

### 六、types 与 Service

**types/api.ts**

- `DocumentTreeItem` 增加 `error_message: string | null`
- 新增 `KnowledgeBaseDetailData`，含 name、description、settings、document_count 等
- 新增 `UpdateKnowledgeBaseRequest`，name、description、settings 均可选

**knowledgeBaseService.ts 新增：**

- `fetchDetail(kbId)` → GET /knowledge-bases/{kb_id}
- `updateKnowledgeBase(kbId, body)` → PATCH
- `deleteKnowledgeBase(kbId)` → DELETE

**documentService.ts 新增：**

- `deleteDocument(documentId)` → DELETE
- `reindexDocument(documentId)` → POST .../reindex

### 七、公共组件

**ConfirmDialog：** 删库和删文档复用同一个组件，基于 shadcn AlertDialog 或现有 Dialog 实现。

**EditKnowledgeBaseDialog：** name Input + description Textarea + settings Textarea，settings 用等宽字体。

**StatusBadge：** 根据 status 数值映射颜色，1 绿色、2 红色、3 黄色或蓝色。

检索页 RetrievePage 本次不改，除非类型报错需要适配。未授权 code=20010 继续走现有 authError 提示。

### 八、验收标准

- 上传文件后很快提示成功，不必等 Worker，列表页出现「索引中」badge
- Worker 跑完后 badge 自动变「成功」，无需手动刷新
- FAILED 文档可见错误信息，点「重试」能再次进入索引流程并最终 SUCCESS
- 知识库可编辑名称和 settings JSON，保存后 retrieve 词表生效
- 可删除单个文档，有二次确认，删除后 retrieve 不再命中
- 可删除整个知识库，有二次确认，删除后 tree 无该库
- 三页 AppHeader 导航正常
- API_KEY 配错后操作提示 20010 错误
