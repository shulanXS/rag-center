# 学习导读

项目背景：rag-center 是一个企业级 RAG（检索增强生成）能力中台，不是一个绑定单一业务场景的应用，而是把检索做成统一 API，让多个租户和业务系统共用同一套能力。覆盖多租户权限体系、分级套餐服务、结构化文档处理、多格式解析、多知识库联合检索、完整效果评估闭环，以及贯穿全程的鲁棒性降级设计。这里提供两条学习路线。

选哪条学习路线？

建议：先 A 读懂项目，再 B 动手重做，理解最深。

---

## 路线 A · 读懂项目

这条路线以现有成品和配套文档为核心，先搞清楚这个中台要解决什么问题、技术上做了哪些关键设计，再深入拆解每一个亮点背后的工程决策。

### 1. 了解项目全景与立意

👉 `难点亮点/00-总览/项目架构全景.md`、`难点亮点/00-总览/项目竞争力：五大亮点.md`

先建立整体印象：rag-center 为什么要做成中台而不是应用？多租户、分级套餐、全链路检索管道、效果评估——这五个方向各自在解决什么真实问题？读完这两篇，你会对整个项目的定位和竞争力有清晰判断，后续读具体模块时也不会迷失方向。

### 2. 本地跑起来

👉 项目根目录 `README.md`（启动方式见其中的「快速开始」章节）

把项目在本地跑通，是理解代码的最短路径。跑通完整流程：启动 Docker 基础设施（PostgreSQL + Elasticsearch + Redis）→ 启动后端 FastAPI 服务 → 启动前端调试台 → 创建租户与 API Key → 创建知识库 → 上传文档（支持 Markdown、Word、PDF）→ 等待异步索引完成 → 在调试台发起检索，切换 vector / bm25 / hybrid 模式，看双路召回分数 → 提交检索反馈 → 查看 Langfuse 链路追踪。

能在浏览器里亲手摸到这些操作，后面读代码会快很多。

### 3. 深入难点亮点

👉 `难点亮点/` 目录

这是含金量最高的部分，按五个专题组织，建议按顺序读：

```
难点亮点/
├── 00-总览/          # 项目架构全景图、五大竞争力概述
├── 01-多租户平台/    # API Key 安全设计、数据隔离策略、Plan 分级功能与配额管控
├── 02-文档处理引擎/  # Celery 异步索引、Markdown 感知分块、多格式解析、重索引策略
├── 03-检索全链路/    # 检索管道总览、查询优化、混合检索+RRF、多知识库联合检索、Profile×Plan 双层约束
├── 04-效果评估体系/  # 检索日志与用户反馈、Langfuse 链路追踪、RAGAS 离线评估
└── 05-工程设计/      # Provider 可插拔抽象、统一错误码体系、健壮性与降级策略
```

每个专题都围绕"为什么这样设计"展开，不只讲实现，重点讲取舍逻辑，是准备技术面试时最有价值的素材。

### 4. 求职收尾

👉 `面试相关/常见面试题.md`、`面试相关/简历.md`

80 道常见面试题覆盖了这个项目每一个设计决策的"为什么"，是准备技术面试的直接素材。简历写法给出了如何把这个中台项目的亮点转化成简历用语，结合自己的实际情况调整后直接用。

## 路线 B · 动手实战

不用现成完整代码，靠 AI 一步步把这个中台项目搭起来。

### 核心方法论：提示词如何落地

👉 `难点亮点/00-总览/项目竞争力：五大亮点.md`

每个功能模块目录里都有两类文件：`00-为什么需要xxx.md` 说清楚这个功能在解决什么问题，`提示词.md` 是直接发给 AI 生成代码的完整提示词。工作方式固定：先读动机文档，再把提示词发给 AI 生成代码，最后对照测试文档验收。不要跳过"为什么需要"这步，没有动机直接看提示词很容易不知道自己在做什么。

### 按提示词逐步搭建

👉 `优化五/` → `优化六/` → … → `优化十四/`

从优化五到优化十四，共十个功能模块，每个目录下的提示词文件按顺序发给 AI 即可。涵盖调试台、多租户鉴权、语义优化、异步索引、分级套餐、效果评估、结构化切块、多格式解析、多知识库联合检索、鲁棒性降级，完整搭出整个中台。

遇到问题先查 `问题记录.md`，记录了开发过程中踩过的坑和对应的解决方法。
