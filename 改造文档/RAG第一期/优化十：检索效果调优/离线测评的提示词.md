# 离线测评提示词

点击此处可复制本篇提示词

离线测评是调优闭环的量化环节：给定一批有标准答案的测例，批量跑 retrieve，用 RAGAS 算检索指标，改配置前后各跑一遍，用数字说话而不是靠体感。测例的主要来源是可观测和反馈阶段在 Langfuse 沉淀的低分记录——越用越贴近真实业务。

## 使用场景

这份提示词用于在当前 rag-center 工程基础上，在可观测和反馈完成后，搭建离线测评体系：从 Langfuse 导出低分反馈候选 → 人工补 `ground_truth` → RAGAS 批量评测 → 对比改配置前后指标。

整套体系由两个独立脚本和一套测例目录组成，不嵌入 FastAPI，不建新表，可单独运行。

### 一、依赖

`pyproject.toml` optional-dependencies 新增 `eval` 组：

```toml
[project.optional-dependencies]
eval = [
  "ragas>=0.2.0",
  "datasets>=2.0.0",
]
```

安装：`pip install -e ".[eval]"`

RAGAS 评测阶段需要调 LLM 做语义判断，`.env` 配置 `MODEL_BASE_URL` 和 `MODEL_API_KEY` 与 rag-center 共用即可。

### 二、目录结构

```
eval/
  datasets/
    ecommerce_retrieval.json          # 主集，已补 ground_truth，作回归基线
    imported_from_feedback.json       # export 原始输出，待审核
    _seed_ecommerce.json              # 冷启动种子，可选，5～10 条
  reports/                            # 评测报告，加入 .gitignore
```

冷启动种子文件 `_seed_ecommerce.json` 是可选的：5～10 条手工种子，对齐 `data/ecommerce/` 文档，确保初期还没有 Langfuse 反馈数据时也能跑通 RAGAS。有了足够的线上反馈后，新增测例以 export 为主。

主集文件 `ecommerce_retrieval.json` 的结构：

```json
{
  "name": "ecommerce_retrieval",
  "kb_id": "939a5baf-xxxx",
  "default_profile": "balanced",
  "cases": [
    {
      "id": "lf_coupon_stack",
      "question": "满减和优惠券能叠加吗？",
      "ground_truth": "同一订单不可同时使用满减活动与店铺优惠券，二者择一适用。",
      "source": {
        "trace_id": "2a86e534-...",
        "feedback_score": 2,
        "feedback_comment": "排第一的不是优惠券规则文档"
      }
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|------|------|------|
| `kb_id` | 是 | 测哪个知识库，export 时从 trace metadata 带出 |
| `default_profile` | 否 | 未在命令行指定 profile 时使用 |
| `cases[].question` | 是 | 调 retrieve 的 query |
| `cases[].ground_truth` | 跑 RAGAS 前必填 | 从知识库原文摘取的关键句，RAGAS 用它来判断召回内容是否覆盖了正确信息；export 阶段可先留空 |
| `cases[].id` | 否 | 建议用 `lf_` 加 trace_id 短码，方便追溯来源 |
| `cases[].source` | 否 | 记录原始反馈分和 trace_id，便于和 Langfuse 对照复盘 |

`ground_truth` 为空的 case 在评测脚本里自动跳过，终端会提示 skipped 数量。

### 三、脚本一：从 Langfuse 导出低分 case

**脚本路径**：`scripts/export_eval_cases_from_langfuse.py`

功能：

1. 读 `.env` 里的 `LANGFUSE_HOST`、`LANGFUSE_PUBLIC_KEY`、`LANGFUSE_SECRET_KEY`
2. 调 Langfuse Public API 拉 score，筛选 `name=user_feedback` 且分值低于阈值的记录，默认阈值为 3
3. 按 `trace_id` 取关联 trace，提取 `input.query`、`metadata.kb_id`、`log_id`、comment
4. 输出 JSON cases：`question` 和 `source` 字段有值，`ground_truth` 默认留空，等待人工填写
5. 支持 `--merge` 模式，追加到已有 dataset，按 `question` 去重，已有 `ground_truth` 的 case 不覆盖
6. 结束时打印导出条数和待补 `ground_truth` 的条数
7. httpx 访问 Langfuse 时关闭系统代理，避免 localhost 502

argparse 参数：

| 参数 | 说明 |
|------|------|
| `--max-score` | 导出分值低于该值的 case，默认 3 |
| `--days` | 只看最近 N 天的反馈 |
| `--kb-id` | 只导出指定知识库的 case，不传则导出全部 |
| `--output` | 输出文件路径 |
| `--merge` | 指定目标 dataset，追加合并而非覆盖 |

命令示例：

```bash
# 导出为独立文件，待审
python scripts/export_eval_cases_from_langfuse.py \
  --max-score 3 \
  --days 30 \
  --kb-id 939a5baf-xxxx \
  --output eval/datasets/imported_from_feedback.json

# 审完 ground_truth 后合并进主集
python scripts/export_eval_cases_from_langfuse.py \
  --max-score 3 \
  --merge eval/datasets/ecommerce_retrieval.json \
  --output eval/datasets/ecommerce_retrieval.json
```

### 四、脚本二：RAGAS 批量评测

**脚本路径**：`scripts/run_retrieval_eval.py`

功能：

1. 读 golden set JSON，跳过 `ground_truth` 为空的 case，终端提示 skipped 数量
2. 逐条调 `POST /api/v1/rag/retrieve`，`user_id` 固定 `eval_runner`
3. 把返回的 chunk 正文列表作为 `contexts` 送入 RAGAS
4. 只评 `context_precision` 和 `context_recall` 两个检索向指标
5. 打印汇总分和每条 case 的得分，`context_recall` 偏低的 case 单独列出
6. 传了 `--output` 时把报告写成 JSON 文件

argparse 参数：

| 参数 | 说明 |
|------|------|
| `--dataset` | golden set JSON 路径 |
| `--api-key` | rag-center API Key |
| `--base-url` | 服务地址，默认 `http://127.0.0.1:8000` |
| `--profile` | 检索策略，默认 `balanced` |
| `--output` | 报告输出路径，可选 |

命令示例：

```bash
# 单独跑反馈导出集，export 后建议先做这步
python scripts/run_retrieval_eval.py \
  --dataset eval/datasets/imported_from_feedback.json \
  --api-key rk_live_你的key \
  --profile balanced \
  --output eval/reports/imported_balanced.json

# 全量回归，种子加已 merge 的 case 一起跑
python scripts/run_retrieval_eval.py \
  --dataset eval/datasets/ecommerce_retrieval.json \
  --api-key rk_live_你的key \
  --profile balanced \
  --output eval/reports/balanced.json

# 改配置前
python scripts/run_retrieval_eval.py --dataset ... --profile balanced \
  --output eval/reports/before_synonyms.json
# 改配置后
python scripts/run_retrieval_eval.py --dataset ... --profile balanced \
  --output eval/reports/after_synonyms.json
```

评测脚本里 `user_id` 固定 `eval_runner`，可以在 Langfuse 里区分评测流量和线上流量。

### 五、和 retrieve 的衔接

每次评测都是用当前配置重新调 retrieve，而不是复用反馈时记录的旧召回结果。这样改了词表或换了 profile 之后，同一批 question 的评测结果才能真实反映新配置的效果，`ground_truth` 不变，retrieve 每次重跑。

retrieve 请求格式：

```json
{
  "kb_id": "...",
  "user_id": "eval_runner",
  "query": "...",
  "profile": "balanced"
}
```

对同一 dataset 跑多个 profile 对比：

```bash
for p in speed balanced quality; do
  python scripts/run_retrieval_eval.py --dataset ... --profile $p \
    --output eval/reports/profile_${p}.json
done
```

### 七、边界说明

- 不建 `feedbacks` 表，测例候选从 Langfuse API 拉
- RAGAS 脚本独立运行，不嵌 FastAPI，不做前端页面
- `ground_truth` 不自动填，export 只出候选，人工补完才能评
- `faithfulness`、`answer_relevancy` 等需要生成答案才能算的指标不在本篇范围，rag-center 只返回 chunk

### 八、验收标准

- export 能拉出分值低于 3 的 case，`ground_truth` 为空字符串
- 人工补 `ground_truth` 后，run eval 输出 `context_precision` 和 `context_recall` 两项指标
- `ground_truth` 为空的 case 自动 skip，终端有提示
- 改 profile 或词表后重跑同一 dataset，报告数值可对比
- 缺 key、知识库不存在、Langfuse 不可用时友好报错，不崩溃
- `eval/reports/` 已加入 `.gitignore`
