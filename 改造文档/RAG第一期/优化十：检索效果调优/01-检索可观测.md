# 01 - 检索可观测

00 讲清了效果调优需要「可观测、可反馈、可量化」三角闭环。这一步先把**可观测**落地：每次 `retrieve` 发生了什么，能在面板里翻出来、能定位到具体一步。

实现上接入 **Langfuse** 做 trace；中台侧保留 `log_id` 和精简的 `retrieval_logs` 写库，不绑死外部工具。反馈 API 和 RAGAS 测评放在 02、03，本篇不动。

## 现状与目标

调试台只能看「当前这一次」，`retrieval_logs` 有写无查，字段偏少；响应里没有 `log_id` / `trace_id`，业务方和 02 的反馈没有关联锚点；也不知道 rewrite / hybrid / rerank 各步的耗时。

本篇把这些补齐：按时间、query、kb 翻历史检索记录；详细现场进 Langfuse，本地只留最小记录；响应回传 `log_id` 和 `trace_id`；trace 子 span 分步记录各阶段耗时。

## 一次 retrieve 要留下什么

```
POST /rag/retrieve
  │
  ├─ Langfuse trace（详细现场）
  │    ├─ span: query_processing   （原话 / effective / search_query、词表、改写）
  │    ├─ span: retrieval          （mode、vector/bm25 命中数、是否降级）
  │    └─ span: rerank             （是否启用、候选数、是否降级）
  │
  ├─ retrieval_logs（本地精简留底）
  │    id, tenant_id, kb_id, query, trace_id, profile, latency_ms, created_at
  │
  └─ 响应 metadata
       log_id, trace_id, latency_ms, …（现有字段保留）
```

Langfuse 里用 metadata 挂租户维度，便于过滤：

```json
{
  "tenant_id": "tenant_demo",
  "kb_id": "939a5baf-...",
  "user_id": "u1",
  "profile": "balanced",
  "plan": "pro"
}
```

## 基础设施：Langfuse 怎么跑

在项目根目录 `docker-compose.yml` 增加 `langfuse-db` 和 `langfuse` 两个 service，与现有 postgres、redis、elasticsearch 并列。Langfuse 使用独立库，不复用 `rag_center` 库。

```bash
docker compose up -d langfuse
```

`.env` 增加：

```env
# Langfuse（01 可观测）
LANGFUSE_ENABLED=true
LANGFUSE_HOST=http://localhost:3000
LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...

# 本地可关，retrieve 行为不变，只是不写 trace
# LANGFUSE_ENABLED=false
```

`langfuse` 服务需配置 `NEXTAUTH_URL=http://localhost:3000` 和 `ENCRYPTION_KEY`，见 `docker-compose.yml`。

macOS 若开了系统代理，Python SDK 访问 `localhost:3000` 可能 502。代码里已对 Langfuse 使用 `httpx.Client(trust_env=False)`，或在环境里设 `NO_PROXY=localhost,127.0.0.1`。

首次启动后在 Web UI 创建项目，复制 public/secret key 填入 `.env`。

依赖：

```toml
# pyproject.toml
"langfuse>=2.0.0,<3.0.0",
```

## 代码怎么接

### 1. Langfuse 客户端封装

新增 `app/observability/langfuse_client.py`：

- 读取 `LANGFUSE_ENABLED`、`LANGFUSE_HOST`、key
- 提供 `get_langfuse()`：未启用时返回 `None`，调用方不抛错
- 提供 `RetrieveObservability`：`start` → 三个 `record_*` span → `finish` + `flush`

### 2. RagService.retrieve 埋点

在 `app/services/rag_service.py` 的 `retrieve` 方法中：

1. 生成 `log_id`，沿用 `retrieval_logs.id` 的 UUID
2. 若 Langfuse 启用，开一条 trace，`name=rag_retrieve`，input 为 `raw_query` + request 摘要
3. **query_processing** 完成后记子 span：output 含 `effective_query`、`search_query`、`synonym_expansions`、是否 degraded
4. **_retrieve_candidates** 记子 span：output 含 mode、vector_count、bm25_count、是否 hybrid degraded
5. **_maybe_rerank** 记子 span：output 含 enabled、candidate_count、degraded
6. trace output：最终 `top_k` 个 chunk 的 `chunk_id` + `score` 摘要，不必塞全文，避免面板过大
7. 写 `retrieval_logs`
8. 响应 `metadata` 增加 `log_id`、`trace_id`

**Langfuse 异常不得影响 retrieve 成功返回**，catch 后打 warning 日志，检索照常。

### 3. retrieval_logs 表扩展

Alembic 迁移 `0006_retrieval_log_observability`，新增字段均可空，兼容旧数据：

```
retrieval_logs 新增：
  trace_id          VARCHAR(64)
  profile           VARCHAR(32)
  search_query      TEXT
  effective_query   TEXT
```

`retrieved_chunks` 等大字段仍写 JSONB 作本地留底；若担心体积，可只存 chunk_id + score 列表，全文以 Langfuse 为准。建议**保持现有 retrieved_chunks 写入**，实现简单。

### 4. 响应 Schema

`RetrieveMetadata` 增加：

```python
log_id: str
trace_id: str | None = None   # Langfuse 未启用时为 null
```

### 5. 配置项

`app/core/config.py`：

```python
langfuse_enabled: bool = False
langfuse_host: str = "http://localhost:3000"
langfuse_public_key: str = ""
langfuse_secret_key: str = ""
```

## 做完怎么验

前置：PostgreSQL、ES、Redis 已启动；Langfuse 容器已起；`.env` 配好 Langfuse key；`LANGFUSE_ENABLED=true`。

### 1. 启动 Langfuse 并配置 Key

```bash
docker compose up -d langfuse
```

浏览器打开 `http://localhost:3000`，注册/登录 → 创建项目 → 复制 Public Key、Secret Key 写入 `.env`，重启后端。

### 2. 跑迁移

```bash
alembic upgrade head
```

确认 `retrieval_logs` 有 `trace_id`、`profile`、`search_query`、`effective_query` 列。

### 3. 发一次 retrieve

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/retrieve \
  -H "Authorization: Bearer rk_live_你的key" \
  -H "Content-Type: application/json" \
  -d '{
    "kb_id": "<kb_id>",
    "user_id": "obs_test",
    "query": "退款几天内可以申请？",
    "profile": "balanced"
  }'
```

预期：`code` 为 0；`data.metadata.log_id` 为非空 UUID；`data.metadata.trace_id` 为非空字符串。记下两个 id。

### 4. Langfuse UI 验 trace

打开 Langfuse → Traces → 找到刚才的 trace，可按 query 或时间筛。

预期：有一条 `rag_retrieve` trace；metadata 含 `tenant_id`、`kb_id`、`profile`；子 span 含 query_processing、retrieval、rerank；input/output 能看清问句变化和召回 chunk 摘要。

### 5. 本地表验留底

```bash
SELECT id, trace_id, profile, search_query, latency_ms
FROM retrieval_logs
ORDER BY created_at DESC
LIMIT 1;
```

预期：`id` 与响应 `log_id` 一致，`trace_id` 与响应一致。

### 6. 关闭 Langfuse 降级

`.env` 设 `LANGFUSE_ENABLED=false`，重启后端，再调一次 retrieve。

预期：检索仍成功；`trace_id` 为 `null`；`log_id` 仍有值；`retrieval_logs` 仍写入。
