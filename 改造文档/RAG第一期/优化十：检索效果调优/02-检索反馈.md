# 02 - 检索反馈

01 已经让每次 retrieve 在 Langfuse 里留下 trace，响应里也回了 `log_id` 和 `trace_id`。但 **知道发生了什么，不等于知道用户满不满意**——运营说「这条检索只有 2 分」，你得能把评价挂到那一次请求上，日后翻出来复盘。

这一步做 **检索反馈**：对某次 retrieve 打 **1～5 分** 并可选写备注，通过 API 写入 Langfuse **score**，和 01 的 trace 关联。调试台在检索结果区 chunk 列表上方提供反馈条；业务方也可直接调 API。反馈在 Langfuse 面板里按 trace 查看，不必自建反馈表。

离线测评（03）和词表/profile 调优，都可以从反馈里捞低分 case，补充进 golden set。

## 现状与目标

目前没有反馈入口，线上「搜不准」沉淀不下来，业务方拿到 chunk 也没有关联 id 可以追溯。这一步补上这三块：提交 1～5 分和备注、用 `log_id` / `trace_id` 关联到某次 retrieve、反馈挂在 trace 上让 Langfuse 可查可统计。

## 反馈怎么关联到某次检索

01 的 retrieve 响应已经返回：

```json
{
  "metadata": {
    "log_id": "a1b2c3d4-...",
    "trace_id": "2a86e534-...",
    "latency_ms": 320
  }
}
```

反馈 API 以 **`trace_id` 为主键** 写入 Langfuse score。同时传 **`log_id`**，方便对账，以及在 `retrieval_logs` 里做租户校验。

```
调试台 / 业务方
    POST /rag/feedback
      { trace_id, log_id?, score: 1-5, comment? }
    → Langfuse: 在该 trace 上创建 score
    → 返回 feedback_id
```

### Score 约定

| 字段 | 说明 |
|------|------|
| `score` | 整数 **1～5**，与调试台五星一致，直接写入 Langfuse `value` |
| `name` | 固定 `user_feedback` |
| `comment` | 可选文字，如「排第一的 chunk 不是退款规则」 |

运营在 Langfuse 可按 `user_feedback <= 2` 筛低分 trace，点开结合 01 的 input/output 复盘。

## 调试台：结果区反馈条

调试台会**连续多次检索**对比，反馈时要能**对照下方 chunk**。因此不用弹窗，在 **「检索与召回」Card 内、chunk 列表上方** 放一条可展开的反馈区：

```
┌─ 检索与召回 ─────────────────────────────────────┐
│ query …                          [检索]          │
│ ── 反馈（有结果且 trace_id 存在时显示）───────── │
│  ★ ★ ★ ★ ☆   （点亮=黄，未点亮=灰，点击选 1～5） │
│  ┌ 备注（可选）──────────────────────────────┐ │
│  │ 排第三的 chunk 才是对的…                    │ │
│  └────────────────────────────────────────────┘ │
│                              [提交反馈]          │
│ ── 召回结果 ─────────────────────────────────── │
│ #1 chunk …                                     │
│ #2 …                                           │
└────────────────────────────────────────────────┘
```

### 交互规则

| 规则 | 说明 |
|------|------|
| 何时显示 | 本次 retrieve **成功** 且 `metadata.trace_id` 非空；无 trace_id 时隐藏并提示「Langfuse 未启用」 |
| 星级 | 5 颗星，点击选 1～5；已选及左侧为**黄色**，右侧未选为**灰色**；提交前 **必选星级** |
| 备注 | 多行输入框，**可选** |
| 提交 | 调 `POST /rag/feedback`，带当前次的 `trace_id`、`log_id`、`score`、`comment` |
| 提交成功 | 简短提示「已提交」；反馈条可显示「已评 N 分」 |
| 再次检索 | **清空**星级与备注，避免挂到新 trace |

反馈条放在 chunk 列表**上方**，写备注时能直接往下看召回内容。

## API 设计

### POST /api/v1/rag/feedback

请求（需鉴权，tenant 由 Key 决定）：

```json
{
  "trace_id": "2a86e534-3ab4-43df-9bbd-e3e78be9273c",
  "log_id": "b7f57ae1-3d0c-49e1-b158-42374f12d015",
  "score": 2,
  "comment": "召回了促销文档，不是交易规则"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `trace_id` | 是 | 01 返回的 Langfuse trace id |
| `log_id` | 建议 | 与 `retrieval_logs` 对账、校验租户 |
| `score` | 是 | 整数 1～5 |
| `comment` | 否 | 备注 |

响应：

```json
{
  "code": 0,
  "data": {
    "feedback_id": "...",
    "trace_id": "...",
    "log_id": "...",
    "score": 2
  }
}
```

### 校验逻辑

1. `trace_id`、`score`（1～5）必填
2. 若传 `log_id`：查 `retrieval_logs`，校验属于当前 `tenant_id`，且 `trace_id` 与记录一致
3. `LANGFUSE_ENABLED=false` 时返回 `20020`，不静默丢反馈
4. Langfuse 写入使用与 01 相同的 `httpx.Client(trust_env=False)`

### 错误码

| code | 含义 |
|------|------|
| `20020` | 反馈失败（Langfuse 不可用等） |
| `20021` | log_id 与 trace_id 不匹配或无权访问 |
| `20022` | score 不在 1～5 |
| `404` | log_id 不存在 |

## 业务方怎么用

典型接入（客服 RAG）：

```
1. 用户提问 → 业务方调 retrieve → 拿到 chunks + trace_id
2. 业务方展示回答，用户打 1～5 分（或简化为低分/高分）
3. 调 POST /rag/feedback，带 trace_id + score + comment
4. 运营在 Langfuse 按 user_feedback <= 2 筛 trace
5. 把 query 补进 03 golden set，改词表或 profile 后再测评
```

rag-center 中台提供 **反馈 API**；完整聊天 UI 在业务方，调试台提供 **结果区反馈条** 便于运营自测。

## 做完怎么验

前置：01 已完成，`LANGFUSE_ENABLED=true`，Langfuse 可访问。

### 1. 先 retrieve，拿到 id

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/retrieve \
  -H "Authorization: Bearer rk_live_你的key" \
  -H "Content-Type: application/json" \
  -d '{
    "kb_id": "<kb_id>",
    "user_id": "fb_test",
    "query": "优惠券能否叠加使用？",
    "profile": "balanced"
  }'
```

记下 `metadata.log_id`、`metadata.trace_id`。

### 2. 提交低分反馈（API）

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/feedback \
  -H "Authorization: Bearer rk_live_你的key" \
  -H "Content-Type: application/json" \
  -d '{
    "trace_id": "<trace_id>",
    "log_id": "<log_id>",
    "score": 2,
    "comment": "排第一的不是优惠券规则文档"
  }'
```

预期：`code` 为 0，`data.score` 为 `2`。

### 3. Langfuse UI 验 score

打开对应 trace → **Scores**。

预期：`user_feedback` 值为 `2`，comment 与提交一致。

### 4. 调试台验反馈条

1. `/retrieve` 检索成功  
2. chunk 列表**上方**出现五星与备注框  
3. 选 4 星、填写备注、提交  
4. Langfuse 该 trace Scores 为 `4`  

### 5. 再次检索

点「检索」发起新请求后，反馈条星级与备注应**已清空**。

### 6. log_id 篡改 / Langfuse 关闭

- 错误 `log_id` → `20021`  
- `LANGFUSE_ENABLED=false` → `20020`；调试台反馈条禁用或隐藏
