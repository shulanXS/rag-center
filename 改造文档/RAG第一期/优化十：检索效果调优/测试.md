## 检索可观测测试

### 1. 启动 Langfuse 并配置 Key

浏览器打开 `http://localhost:3000`，注册登录后创建项目，复制 Public Key 和 Secret Key 写入 `.env`，重启后端。

### 2. retrieve 响应含可观测字段

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/retrieve \
  -H "Authorization: Bearer rk_live_REDACTED" \
  -H "Content-Type: application/json" \
  -d '{
    "kb_id": "df1dad54-7bfd-4ec7-9116-cfe2448e9389",
    "user_id": "obs_test",
    "query": "退款几天内可以申请？",
    "profile": "balanced"
  }'
```

预期：`code` 为 0，`data.metadata.log_id` 为非空 UUID，`data.metadata.trace_id` 为非空字符串。记下这两个值供后续步骤使用。

### 3. Langfuse UI 验 trace

打开 Langfuse → Traces，可按 query 关键词或时间筛选到刚才的记录。

预期：

1. 有一条名为 `rag_retrieve` 的 trace
2. trace metadata 含 `tenant_id`、`kb_id`、`profile`
3. 子 span 含 `query_processing`、`retrieval`、`rerank` 三条
4. 点开 span 能看到问句变化和召回 chunk 摘要

### 4. 本地表验留底

```bash
SELECT id, trace_id, profile, search_query, latency_ms
FROM retrieval_logs
ORDER BY created_at DESC
LIMIT 1;
```

预期：`id` 与响应 `log_id` 一致，`trace_id` 与响应 `trace_id` 一致。

### 5. 关闭 Langfuse 后的降级行为

`.env` 改为 `LANGFUSE_ENABLED=false`，重启后端，再发一次 retrieve。

预期：检索仍成功，`trace_id` 为 `null`，`log_id` 仍有值，`retrieval_logs` 仍正常写入。

## 检索反馈测试

前置：可观测测试已通过，`LANGFUSE_ENABLED=true`。

### 1. 先 retrieve，拿到关联 id

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/retrieve \
  -H "Authorization: Bearer rk_live_REDACTED" \
  -H "Content-Type: application/json" \
  -d '{
    "kb_id": "df1dad54-7bfd-4ec7-9116-cfe2448e9389",
    "user_id": "fb_test",
    "query": "优惠券能否叠加使用？",
    "profile": "balanced"
  }'
```

记下 `metadata.log_id` 和 `metadata.trace_id`。

### 2. 通过 API 提交低分反馈

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/feedback \
  -H "Authorization: Bearer rk_live_REDACTED" \
  -H "Content-Type: application/json" \
  -d '{
    "trace_id": "39b43b0c-b962-4e63-a8f9-343a37605a9c",
    "log_id": "faa5ad86-3158-4c40-ad21-fec338ec2369",
    "score": 2,
    "comment": "排第一的不是优惠券规则文档"
  }'
```

预期：`code` 为 0，`data.score` 为 `2`。

### 3. Langfuse UI 验 score

打开对应 trace，切到 **Scores** 标签页。

预期：`user_feedback` 值为 `2`，comment 与提交内容一致。

### 4. 调试台验反馈条

1. 打开 `/retrieve`，填入有效参数，点「检索」
2. 检索成功后，chunk 列表上方出现五星组件与备注输入框
3. 选 4 星，填写备注，点「提交反馈」
4. Langfuse 对应 trace 的 Scores 值为 `4`

### 5. 再次检索后清空反馈

点「检索」发起新一轮请求后，反馈区的星级与备注应已自动清空，不会带到新 trace。

### 6. 异常场景

| 场景 | 预期 |
|------|------|
| 传错误 `log_id`，与 `trace_id` 不匹配 | `code` 为 `20021` |
| `score=0` 或 `score=6` | `code` 为 `20022` |
| `LANGFUSE_ENABLED=false` 时调 feedback | `code` 为 `20020` |
| `LANGFUSE_ENABLED=false` 时打开调试台 | 反馈条隐藏，或出现「Langfuse 未启用」提示 |

## 离线测评测试

前置：Langfuse 里已有若干低于 3 分的反馈，或准备好种子集；知识库已索引；`.env` 配好 `LANGFUSE_*` 和 `MODEL_*`；已执行 `pip install -e ".[eval]"`。

### 1. 从 Langfuse 导出低分 case

```bash
python scripts/export_eval_cases_from_langfuse.py \
  --max-score 3 \
  --days 30 \
  --kb-id df1dad54-7bfd-4ec7-9116-cfe2448e9389 \
  --output eval/datasets/imported_from_feedback.json
```

预期：

1. 输出 JSON 含 `question`、`source.feedback_score`、`source.feedback_comment`
2. `ground_truth` 字段为空字符串
3. 终端打印导出条数和待补 `ground_truth` 的条数

### 2. 人工补 ground_truth

打开对应知识库文档，为每条 case 摘 1～2 句关键话填入 `ground_truth`。RAGAS 用这段话做语义判断，不要求字面一致，但要准确覆盖问题的核心答案。

### 3. 单独跑反馈集

```bash
python scripts/run_retrieval_eval.py \
  --dataset eval/datasets/imported_from_feedback.json \
  --api-key rk_live_REDACTED \
  --profile balanced \
  --output eval/reports/imported_balanced.json
```

预期：

1. 只评 export 出来的几条，`ground_truth` 为空的 case 被 skip，终端有提示
2. 终端显示汇总分，含 `context_precision` 和 `context_recall`，以及每条 case 的得分
3. `eval/reports/imported_balanced.json` 已生成

### 4. 合并进主集（可选）

```bash
python scripts/export_eval_cases_from_langfuse.py \
  --max-score 3 \
  --merge eval/datasets/ecommerce_retrieval.json \
  --output eval/datasets/ecommerce_retrieval.json
```

预期：主集追加了新 question，已有 `ground_truth` 的 case 未被覆盖。

### 5. 全量 RAGAS 评测

```bash
python scripts/run_retrieval_eval.py \
  --dataset eval/datasets/ecommerce_retrieval.json \
  --api-key rk_live_REDACTED \
  --profile balanced \
  --output eval/reports/balanced.json
```

预期：种子和已 merge 的 case 一起评，报告生成，两项指标均有值。

### 6. 对比改配置前后

1. 记录当前报告的两项指标分数
2. 修改词表或切换到 `--profile quality`
3. 用同一命令再跑一遍，输出到 `eval/reports/after_synonyms.json`
4. 对比 `context_recall` 是否提升

### 7. 异常场景

| 场景 | 预期 |
|------|------|
| `--api-key` 无效 | 友好报错，提示检查 Key |
| 知识库不存在 | retrieve 报错，脚本输出失败 case，不崩溃 |
| Langfuse 不可用时跑 export | 友好报错，提示连接失败 |
| `MODEL_API_KEY` 未配置 | RAGAS 报错，提示配置 LLM key |
