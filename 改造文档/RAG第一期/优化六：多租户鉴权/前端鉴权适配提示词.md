# 设计前端鉴权适配提示词

点击此处可复制本篇提示词

后端鉴权完成后，前端要同步改：用拦截器自动带 Key，去掉三个页面的 tenant_id 输入，列表页改成两级展示。这是一次纯前端改造，不新增页面，改完后用户感知上变化不大，只是操作时不再需要手动填租户 ID。

## 使用场景

这份提示词依赖后端鉴权（01、02）已完成。此时后端四个业务接口不再接收 body 里的 `tenant_id`，改由 `Authorization: Bearer` 请求头传 Key，服务端自己解析租户。未授权时响应 body 里 `code=20010`（HTTP 状态码仍为 200）。

前端需要做两件事：

1. `http.ts` 请求拦截器自动给每个请求加上 `Authorization: Bearer <key>`，Key 来自 `frontend/.env` 的 `API_KEY`
2. 三个页面去掉 tenant_id 相关字段和输入框，列表页从三级展开改为两级（知识库 → 文档）

不做登录页、不做多租户切换 UI、不用 sessionStorage 存 Key。

### 一、功能目标

- `http.ts` 拦截器读取 `import.meta.env.API_KEY`，自动设置请求头
- 响应 `code=20010` 时给出明确错误提示，文案引导用户检查 `.env` 配置
- 三个页面表单和 payload 去掉 `tenant_id`
- 列表页从三级（租户→知识库→文档）改为两级（知识库→文档），标题右侧展示当前租户
- 更新 types、services，新增 `.env.example`

### 二、http.ts 拦截器

读取 `import.meta.env.API_KEY`，有值时请求拦截器设置：

```
Authorization: Bearer <key>
```

响应拦截器检查 body 里 `code === 20010` 时，给出明确提示：

> API Key 无效或未配置，请检查 frontend/.env 中的 API_KEY

Toast 或页面顶部 Banner 均可，不必单独做登录页。

### 三、上传页（`/`）

- 创建知识库表单：去掉 `tenant_id` 输入，只留名称、描述
- 上传表单：去掉 `tenant_id`，只留 `kb_id` 和文件选择
- create 成功后响应里仍会带 `tenant_id`，展示为 Badge 只读即可
- 从列表页跳转过来时，URL 只带 `kb_id`（不再带 `tenant_id`）

### 四、列表页（`/knowledge-bases`）

**改为两级展示**

后端 tree 接口现在只返回一个 tenant，前端 flatMap 数据即可，不必改接口：

```
▶ A的知识库  kb_id: 939a5baf…   [展开/收起]
    backend_engineer.md    document_id  chunk_count
    frontend_engineer.md   …
▶ B的知识库  kb_id: …
```

**标题展示当前租户**

调用 `GET /auth/me`，在页面标题右侧展示：

- 当前租户名称：`<tenant_name>`（Badge 样式）
- 当前租户 ID：`<tenant_id>`（Badge 样式）

**搜索框**

原来按 `tenant_id` 搜索，改为按知识库名称模糊搜索（与后端 tree `keyword` 对齐）。

**ID 列**

- 表头：`kb_id/document_id`
- 知识库行显示 `kb_id`，文档行显示 `document_id`

**跳转链接**

去上传、去检索的跳转 URL 只带 `kb_id`，不带 `tenant_id`。

### 五、检索页（`/retrieve`）

- 检索范围区：去掉 `tenant_id` 输入，只留 `kb_id`
- `buildRetrievePayload` 不传 `tenant_id`
- 从列表页跳转时 URL 只预填 `kb_id`
- 检索参数标签旁新增 `HelpTooltip`，悬停可看各参数的通俗说明，覆盖：`top_k`、检索模式、hybrid 子参数（`vector_top_k` / `bm25_top_k` / `rrf_k`）、`rerank`
- `HelpTooltip` 为公共组件，召回结果里 chunk 指标 tooltip 也可复用

### 六、types 与 Service

**types/api.ts**

- `CreateKnowledgeBaseRequest`、`UploadDocumentRequest`、`RetrieveRequest` 移除 `tenant_id`
- 响应类型若仍有 `tenant_id` 可保留（只读展示）
- 新增 `AuthMeData`

**services**

- `createKnowledgeBase`、`uploadDocument`、`retrieve`、`fetchTree`：payload 不传 `tenant_id`
- 新增 `authService.ts`，提供 `fetchAuthMe()`

### 七、环境变量与配置

新增 `frontend/.env.example`：

```env
VITE_API_BASE_URL=
API_KEY=rk_live_your_key_here
```

`vite.config.ts`：`envPrefix` 含 `API_`，否则 Vite 不会把 `API_KEY` 暴露给客户端。`vite-env.d.ts` 补充 `ImportMetaEnv`。

`.gitignore` 确认 `frontend/.env` 不被提交。README 前端章节说明配置 API_KEY 的步骤（先用 `scripts/create_api_key.py` 生成 Key，再写入 `.env`）。

本地若前后端都想免 Key 调试：后端 `AUTH_ENABLED=false`，前端 `API_KEY` 留空，拦截器不传 Header。

### 八、验收标准

- `frontend/.env` 配好正确 Key，依次创建知识库、上传文档、检索——三页表单里均无 tenant_id 输入框，操作全部成功
- 列表页标题右侧展示当前租户名称和 ID，表格为两级（知识库→文档），跳转链接只带 `kb_id`
- 把 `API_KEY` 改成乱码刷新，触发任意操作后出现 `code 20010` 的错误提示
- 后端 `AUTH_ENABLED=false` 且 `API_KEY` 留空时，本地照常调试
