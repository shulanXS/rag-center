# 03 - 前端鉴权适配

01、02 后端已完成：四个业务接口通过 Header 里的 API Key 识别租户，请求体里不再需要 `tenant_id`。

前端本篇要做两件事：**（1）** 在 `frontend/.env` 配置 `API_KEY`，由 `http.ts` 拦截器给每个请求自动加上 `Authorization: Bearer ...`；**（2）** 上传、列表、检索三页去掉 tenant_id 输入框，URL 和接口 payload 也不再传 `tenant_id`。不做连接页、不做登录页。

## 配置方式

```
frontend/.env
  API_KEY=rk_live_xxx        ← 部署时配置，不进 git

frontend/src/lib/http.ts
  每个请求自动加 Header: Authorization: Bearer rk_live_xxx
```

用户打开页面就能直接操作，感知上和现在差不多，只是不再需要手动填 tenant_id。

切换租户 = 换一把 Key、改 `.env`、重启前端 dev server（或重新构建）。一个部署环境对应一个租户，符合中台给业务方单独发 Key 的用法。

## 各页面怎么改

### 上传页 `/`

- 创建知识库表单：去掉 `tenant_id` 输入，只留名称、描述
- 上传表单：去掉 `tenant_id`，只留 `kb_id` 和文件选择
- 从列表页跳转过来时，URL 只带 `kb_id`（不再带 `tenant_id`）

### 列表页 `/knowledge-bases`

- 顶部搜索框：按知识库名称模糊搜索（对应 `GET /tree?keyword=`）
- 表格**两级**：知识库 → 文档（去掉租户展开层；后端 tree 仍返回 `TenantTreeItem[]`，前端 flatMap 即可，**不必改接口**）
- 标题右侧展示当前租户：`GET /auth/me` 取 `tenant_name`、`tenant_id`，文案为「当前租户名称：」「当前租户 ID：」，值用 Badge 标签样式
- ID 列：表头 `kb_id/document_id`；知识库行显示 `kb_id`，文档行显示 `kb_id/document_id`
- 跳转链接：`?kb_id=xxx`，不带 tenant_id

### 检索页 `/retrieve`

- 检索范围区：去掉 `tenant_id` 输入，只留 `kb_id`
- 从列表页「去检索」跳转：URL 只带 `kb_id`
- 检索参数区：`top_k`、检索模式，以及 hybrid 下的 `vector_top_k` / `bm25_top_k` / `rrf_k`、`rerank` 等标签旁有问号图标，悬停可看各参数的通俗说明，方便调参时对照理解（与下方召回结果里 chunk 指标的 tooltip 共用 `HelpTooltip`）

### 公共

- `types/api.ts`：请求类型去掉 `tenant_id`；补充 `AuthMeData`
- `documentService`、`knowledgeBaseService`、`ragService`、`authService`：payload 不传 tenant_id；`authService.fetchAuthMe` 供列表页展示租户
- `http.ts`：请求拦截器读 `import.meta.env.API_KEY` 写 Authorization
- `vite.config.ts`：`envPrefix` 含 `API_`，否则 Vite 不会把 `API_KEY` 暴露给客户端
- 未授权（响应 body 里 `code: 20010`，HTTP 状态码通常仍为 200）：提示「API Key 无效或未配置，请检查 frontend/.env 中的 API_KEY」（Toast 或页面顶部 Banner 均可，不必单独做登录页）

## 环境变量与示例文件

新增 `frontend/.env.example`：

```env
VITE_API_BASE_URL=
API_KEY=rk_live_your_key_here
```

`.gitignore` 确保 `frontend/.env` 不被提交。README 补一句：前端开发前先 `cp frontend/.env.example frontend/.env` 并填入 01 脚本（`scripts/create_api_key.py`）生成的 Key。

后端 `.env.example` 补充（若 01 未写）：

```env
AUTH_ENABLED=true
```

本地若前后端都想免 Key 调试：后端 `AUTH_ENABLED=false`（固定 tenant_demo，代码内常量），前端 `API_KEY` 可留空，拦截器不传 Header。

## 这篇做什么、不做什么

本篇只做前端：http 拦截器自动带 Key、三页去掉 tenant_id 输入框、列表页改两级树并展示当前租户、更新 types/services、新增 `.env.example`。不做连接页、不做多租户切换 UI、不用 sessionStorage 存 Key。

## 做完怎么验

1. **完整链路**：`frontend/.env` 配好正确 Key，打开页面，依次创建知识库、上传文档、在检索页召回——三页表单里均无 tenant_id 输入框，操作全部成功。
2. **租户展示**：列表页标题旁显示当前租户名称和 ID（来自 `/auth/me`），表格只有两级（知识库→文档）；点「去上传」「去检索」跳转时 `kb_id` 已带入。
3. **Key 无效提示**：把 `API_KEY` 改成乱码刷新，触发任意操作后页面出现 `code 20010` 的错误提示。
