# 多租户鉴权测试验收

## 测试准备

`AUTH_ENABLED=true`，后端已启动。先用脚本建好两个租户和对应 Key：

```bash
python scripts/create_tenant.py --id tenant_a --name "租户A"
python scripts/create_api_key.py --tenant-id tenant_a --name "Key A"
# 记下 Key A 明文，下文以 KEY_A 代替

python scripts/create_tenant.py --id tenant_b --name "租户B"
python scripts/create_api_key.py --tenant-id tenant_b --name "Key B"
# 记下 Key B 明文，下文以 KEY_B 代替
```

## 后端基础设施测试

### 1. 迁移与表结构

```bash
alembic upgrade head
```

预期：`tenants`、`api_keys` 两张表创建成功。

### 2. 创建租户

```bash
python scripts/create_tenant.py --id tenant_demo --name "演示租户"
```

预期：终端提示创建成功。重复执行相同 `--id` 应报错（租户已存在）。

### 3. 创建 API Key

```bash
python scripts/create_api_key.py --tenant-id tenant_demo --name "本地开发"
```

预期：终端打印明文 Key（如 `rk_live_abc123...`），只出现这一次，请立即复制。租户不存在时应报错。

### 4. 带正确 Key 调 /auth/me

```bash
curl -s http://127.0.0.1:8000/api/v1/auth/me \
  -H "Authorization: Bearer rk_live_你的key"
```

预期：`code` 为 0，`data` 含 `tenant_id: "tenant_demo"`、`tenant_name`、`key_prefix`、`key_name`。

### 5. 不带 Key 调 /auth/me

```bash
curl -s http://127.0.0.1:8000/api/v1/auth/me
```

预期：`code` 为 20010（UNAUTHORIZED）。

### 6. 带错误 Key 调 /auth/me

```bash
curl -s http://127.0.0.1:8000/api/v1/auth/me \
  -H "Authorization: Bearer rk_live_invalid_key_12345"
```

预期：`code` 为 20010。

### 7. 关闭鉴权（本地调试）

`.env` 改为 `AUTH_ENABLED=false`，重启后端：

```bash
curl -s http://127.0.0.1:8000/api/v1/auth/me
```

预期：不带 Key 也能成功，`tenant_id` 固定为 `tenant_demo`。

## 业务 API 隔离测试

以下测试前提：`AUTH_ENABLED=true`，两个租户和 Key 已按准备步骤建好。

### 1. Key A 创建知识库

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/knowledge-bases/create \
  -H "Authorization: Bearer KEY_A" \
  -H "Content-Type: application/json" \
  -d '{"name":"A的知识库","description":""}'
```

预期：`code` 为 0，`data.tenant_id` 为 `tenant_a`。记下返回的 `kb_id`，下文以 `KB_ID_A` 代替。

### 2. Key A 上传文档

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/documents/upload \
  -H "Authorization: Bearer KEY_A" \
  -H "Content-Type: application/json" \
  -d '{"kb_id":"KB_ID_A","title":"测试文档","content":"这是一段用于检索验证的测试内容。"}'
```

预期：`code` 为 0。

### 3. Key A 检索

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/retrieve \
  -H "Authorization: Bearer KEY_A" \
  -H "Content-Type: application/json" \
  -d '{"kb_id":"KB_ID_A","user_id":"test_user","query":"测试内容"}'
```

预期：`code` 为 0，有召回结果。

### 4. Key A 调 tree（只能看到自己的数据）

```bash
curl -s http://127.0.0.1:8000/api/v1/knowledge-bases/tree \
  -H "Authorization: Bearer KEY_A"
```

预期：结果中只有 `tenant_a` 及其知识库，不含 `tenant_b` 的数据。

### 5. Key B 调 tree（看不到 A 的数据）

```bash
curl -s http://127.0.0.1:8000/api/v1/knowledge-bases/tree \
  -H "Authorization: Bearer KEY_B"
```

预期：结果中只有 `tenant_b`，不含 A 的知识库。

### 6. Key B 用 A 的 kb_id 检索（应失败）

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/retrieve \
  -H "Authorization: Bearer KEY_B" \
  -H "Content-Type: application/json" \
  -d '{"kb_id":"KB_ID_A","user_id":"test_user","query":"测试"}'
```

预期：`code` 非 0，提示知识库不存在。

### 7. 不带 Key 调业务接口

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/knowledge-bases/create \
  -H "Content-Type: application/json" \
  -d '{"name":"无Key测试","description":""}'
```

预期：`code` 为 20010（UNAUTHORIZED）。

## 前端链路测试

### 1. 完整创建与检索流程

`frontend/.env` 配好正确 Key，打开页面：

1. 创建新知识库，表单里确认无 tenant_id 输入框，提交成功
2. 上传文档，表单里确认无 tenant_id 输入框，提交成功
3. 在检索页输入 query，检索范围区确认只有 kb_id 输入，无 tenant_id，召回结果正常

### 2. 列表页租户展示与两级结构

1. 打开 `/knowledge-bases`，标题右侧显示当前租户名称和 ID（Badge 样式）
2. 表格为两级：知识库→文档，无租户展开层
3. 搜索框按知识库名称过滤（不再按 tenant_id 搜）
4. 点击「去上传」跳转，URL 只带 `kb_id`，表单 tenant_id 输入框不存在
5. 点击「去检索」跳转，URL 只带 `kb_id`，检索范围区只有 kb_id 预填

### 3. Key 无效提示

1. 把 `frontend/.env` 里的 `API_KEY` 改成乱码，重启 dev server
2. 触发任意操作（如创建知识库）
3. 预期：页面出现 `code 20010` 相关的错误提示，提示检查 API_KEY 配置

### 4. 本地免 Key 调试

1. 后端 `AUTH_ENABLED=false`，前端 `.env` 的 `API_KEY` 留空
2. 预期：所有操作照常，自动用 `tenant_demo` 租户
