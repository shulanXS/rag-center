# 02 - 表格专项切块

01 已经能按 `#` / `##` 切 Markdown 了（`###` 及以下随节走），普通段落、列表会跟着当前节走。但 **表格是另一回事**——01 里表格仍随节切，节内过长时还是可能在某一行中间被字符切掉。

电商、制度类文档里表格很常见，如《促销活动与优惠券使用规则》《商品上架与类目合规规范》。用户问「某种场景下规则是什么」，答案往往在 **表格的某一行**，表头和该行必须在同一个 chunk 里才有完整语义。

本篇在 01 的 splitter 上 **增加表格识别与专用切法**。

## 01 解决不了的问题

假设某节里有：

```markdown
## 叠加规则

| 场景 | 是否可叠加 | 说明 |
| 满减 + 优惠券 | 否 | 同一订单只能选一种 |
| 会员折扣 + 券 | 是 | 需满足会员等级 |
```

若这一节整体超过 800 字符，01 的节内字符切可能变成：

```
chunk A: …| 满减 + 优惠券 | 否 | 同一…
chunk B: …订单只能选一种 |\n| 会员折扣…
```

用户问「满减和券能叠加吗」，向量检索很难匹配到 **不完整的那半行**。

## 目标行为

1. **识别 Markdown 表格**：连续 `| ... |` 行视为一张表
2. **小表整表进一个 chunk**（不超过 `chunk_size` 时）
3. **大表按行组切**：每组带 **完整表头行** + 若干数据行；metadata 标记 `chunk_type: "table"`
4. **表前说明文字**（如「## 叠加规则」下的引言）单独或与相邻段落成块，不强行和表粘在一起

切完示例：

| content | metadata |
|---------|----------|
| 表头 + 第 1～3 行 | `chunk_type: "table"`, `heading_path: ".../叠加规则"`, `table_part: 1` |
| 表头 + 第 4～6 行 | `chunk_type: "table"`, `table_part: 2` |

表头注入：每个 table chunk 的 content 开头应是：

```markdown
【表头】场景 | 是否可叠加 | 说明
| 满减 + 优惠券 | 否 | …
```

具体格式实现时可简化，关键是语义完整。

## 实现思路

在 `MarkdownStructuredSplitter` 中增加 **块级扫描**：

```
当前节 buffer 内扫描
  ↓
遇到表格起始行（| 开头且含 |）→ 进入 table 模式
  ↓
收集连续表格行直到非表格行
  ↓
若整张表 <= chunk_size → 输出一个 table chunk
若超过 → 保留 header，按 N 行一组切，每组 chunk 都 repeat header
  ↓
非表格内容仍走 01 的段落/字符逻辑
```

**配置（可选，.env 或 constants）：**

| 变量 | 含义 | 建议默认 |
|------|------|----------|
| `TABLE_MAX_ROWS_PER_CHUNK` | 大表每组最多数据行（不含表头） | 10 |
| `CHUNK_SIZE` | 仍作为硬上限 | 800 |

## 给 AI 的提示词

```
在 rag-center 项目完成「优化十一 - 02 表格专项切块」（依赖 01 Markdown 标题切块已完成）。

【1. 扩展 MarkdownStructuredSplitter】
- 在节内扫描时识别 Markdown 表格（连续 |...| 行）
- 小表：整表一个 chunk，chunk_type=table
- 大表：每组带完整表头行 + 最多 TABLE_MAX_ROWS_PER_CHUNK 数据行；metadata table_part 递增
- 表头行识别：第一行 | 或分隔行 |---| 下一行为 header（标准 MD 表格）
- 每个 table chunk content 顶部可重复一行表头摘要，便于 embedding
- 表格与前后段落分开切块，不跨类型硬拼

【2. 配置】
- settings 增加 TABLE_MAX_ROWS_PER_CHUNK（默认 10），可选

【3. 测试】

- 大表分组且每组含表头
- 混合：标题 + 段落 + 表 + 段落

【边界】
- 不做 reindex 脚本（03）
- 不改 retrieve

【验收】

```

## 做完怎么验

### 1. 上传含表格的文档

使用 `data/ecommerce/促销活动与优惠券使用规则.md` 或精简版测试内容，上传到测试 kb。

### 2. 检查 chunk

- 检索「满减和优惠券能否叠加」或类似 query
- 调试台 Top chunk 应包含 **完整表头 + 对应数据行**
- 不应出现只有 `| 否 | 同一订单` 这种残片

### 3. 对比 01 -only 行为（可选）

若保留了旧 `TextSplitter`，对同一文档对比 chunk 边界，表格相关 chunk 明显更完整。
