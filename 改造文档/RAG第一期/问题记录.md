# 问题记录

## 1. Elasticsearch 缺少 IK 中文分词插件

### 现象

上传文档时报错：**「关键词检索服务异常」**（`code=30005`）。

日志关键信息：

```
KEYWORD_INDEX_INIT_FAILED | provider=elasticsearch | index=rag_chunks
Client error '400 Bad Request' for url 'http://localhost:9200/rag_chunks'

response_body:
Unknown analyzer type [ik_smart] for [default]
```

调用链：文档分块 → Embedding 成功 → 写入 pgvector 成功 → **创建 ES 索引 `rag_chunks` 失败** → 整次上传失败。

### 原因

`app/providers/keyword_search/elasticsearch.py` 中索引配置使用了 IK 中文分词器：

- 默认分词器：`ik_smart`
- `title` / `content` 字段：`ik_max_word`（索引）、`ik_smart`（检索）

而 `docker-compose.yml` 原先使用的官方镜像 `docker.elastic.co/elasticsearch/elasticsearch:8.17.10` **未预装 IK 插件**。ES 不认识 `ik_smart` / `ik_max_word`，创建索引时返回 400。

> 说明：此问题与「httpx 走系统代理导致 ES 502」是不同问题；502 修复后仍会命中本问题。

### 解决方式

在官方 ES 镜像基础上自建带 IK 的镜像，并恢复代码中的 IK 索引配置。

**1. 新增 `Dockerfile.elasticsearch`**

```dockerfile
FROM docker.elastic.co/elasticsearch/elasticsearch:8.17.10
RUN bin/elasticsearch-plugin install --batch \
    https://get.infini.cloud/elasticsearch/analysis-ik/8.17.10
```

**2. 修改 `docker-compose.yml`**

```yaml
elasticsearch:
  build:
    context: .
    dockerfile: Dockerfile.elasticsearch
  image: rag-center-elasticsearch:8.17.10-ik
```

**3. 重建并启动 ES**

```bash
docker compose up -d --build elasticsearch
```

**4. 验证 IK 已加载**

```bash
curl 'http://localhost:9200/_cat/plugins?v'
# 应看到 analysis-ik 8.17.10
```

**5. 若之前用 standard 分词建过旧索引，需删除后重建**

```bash
curl -X DELETE http://localhost:9200/rag_chunks
```

重启 rag-center 后端，重新上传文档即可；应用会在首次写入时按 IK 配置自动创建索引。

### 备注

- IK 插件版本需与 ES 版本一致（当前均为 **8.17.10**）。
- 临时方案（不推荐长期使用）：将索引配置改为 ES 内置 `standard` 分词，无需 IK，但中文 BM25 / hybrid 检索效果较差。
