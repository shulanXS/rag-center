# 01 - 知识库列表页

调试台能创建知识库、上传文档，但有个明显痛点：库建好了，关掉浏览器就找不回来了。

列表页就是来补这块的——把数据按 **租户 → 知识库 → 文档** 三级结构展示出来，不用再翻数据库或靠死记 UUID。

## 界面长什么样

页面顶部是一个搜索框，输入关键字可过滤租户。这里只搜 **租户 ID**，支持模糊匹配——比如输入 `tech`，就能把 `tech_position` 筛出来。

搜索框下方是一张可以逐层展开的表格。调试台数据量不大，**不做分页**，直接把符合条件的全部加载出来。

```
▶ tech_position                          [展开/收起]
    ▶ 技术岗位知识库  kb_id: 939a5baf…   [展开/收起]
        backend_engineer.md    document_id  chunk_count
        frontend_engineer.md   …
    ▶ 面试题库  kb_id: …
▶ tenant_demo
    …
```

在知识库行，可以复制 `kb_id`、跳转到上传页或检索页，跳转时会自动带上对应的 `tenant_id` 和 `kb_id`，无需手填。

文档层**只展示上传成功**（`status=SUCCESS`）的记录，失败或处理中的文档不在列表出现。分块明细也不在这里展示，那是检索页该看的内容。

## 前后端各要做什么

**后端** 新增一个树形查询接口，一次把「租户 → 知识库 → 文档」三级数据查回来。搜索关键字只过滤租户 ID，文档层只返回上传成功的记录。鉴权、分页、删除不做，调试台用不到。

**前端** 新增 `/knowledge-bases` 路由，实现三级可展开表格和顶部搜索；把顶栏抽成公共组件 `AppHeader`，供上传页、列表页、检索页共用；首页 `/` 的上传逻辑保持不变。UI 继续用项目已有的 shadcn/ui 组件，Table 组件按需补装，展开收起用状态自己实现，不引额外 UI 库。

## 开发提示词

```
在 rag-center 项目一步完成「知识库列表页 + 顶部导航」（RAG 调试台）：

【后端】
- 新增 GET /api/v1/knowledge-bases/tree?keyword=（keyword 可选，模糊匹配 tenant_id）
- 返回三级结构，不分页，例如：
  data: [
    {
      tenant_id: "...",
      knowledge_bases: [
        {
          kb_id, name, description, created_at,
          documents: [
            { document_id, title, status, chunk_count, created_at }
          ]
        }
      ]
    }
  ]
- 按 tenant_id 分组；知识库按 created_at 倒序；文档按 created_at 倒序
- Repository/Service 实现查询与组装；风格与现有 API 一致
- 不做鉴权、分页、删除

【前端】
- 路由：/ 保持 KnowledgeUploadPage（首页上传）；/knowledge-bases 新增 KnowledgeFileTreePage
- 公共组件 AppHeader：左侧「RAG 知识文件管理」，右侧根据当前路由显示其他页入口：
  - 在 / → 右侧：知识库列表(/knowledge-bases)、检索调试(/retrieve 占位)
  - 在 /knowledge-bases → 右侧：知识库上传(/)、检索调试(/retrieve)
  - 在 /retrieve → 右侧：知识库上传(/)、知识库列表(/knowledge-bases)
- 列表页：顶部 keyword 搜索（过滤 tenant_id）；三级可展开表格（租户→知识库→文档）；文档层只展示上传成功的记录
- 知识库行：复制 kb_id、去上传/检索（query: tenant_id, kb_id）
- 不使用 localStorage
- UI 沿用现有 shadcn/ui
- knowledgeBaseService 增加 fetchTree(keyword?)

范围最小。验收：多租户多库多文档能树形展示；仅成功文档出现在文档层；搜 tenant_id 有效；从列表跳转上传时 tenant_id、kb_id 已带入。
```

## 验收方式

在同一个租户下建两个知识库、各上传几份文档（包含故意失败的），然后打开列表页确认：

- 三级结构是否正确展开
- 文档层是否**只显示上传成功**的文件
- 搜索框能否按租户 ID 过滤

再从知识库行点「去上传」，确认跳转后 `tenant_id` 和 `kb_id` 已自动填好。最后回首页 `/`，确认上传页正常、顶栏右侧能看到「知识库列表」入口。
