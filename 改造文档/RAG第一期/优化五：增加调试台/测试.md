# 知识库列表页与检索调试页测试验收

## 测试准备

在同一个租户下建两个知识库，各上传几份文档（包含故意失败的）。确保至少有两个不同的租户 ID，方便验证搜索过滤。

## 知识库列表页测试

### 1. 三级结构正确性

打开 `/knowledge-bases`，展开各层级：

1. 最外层按租户分组，每个租户是独立可展开行
2. 展开租户后，下方是该租户的知识库列表，每个知识库显示 name 和 kb_id（截断）
3. 展开知识库后，下方是文档列表，显示 title、document_id、chunk_count

### 2. 文档状态过滤

故意失败的文档和处理中的文档不应出现在文档层。只有 `status=SUCCESS` 的文档可见。上传几份处理失败的文档后刷新列表，确认它们不在树里。

### 3. 搜索过滤

1. 搜索框输入 `tech`，只显示 `tenant_id` 中含 `tech` 的租户（比如 `tech_position`），其他租户消失
2. 清空搜索框，所有租户恢复显示
3. 搜索一个不存在的字符串，列表为空

### 4. 跳转带参

从知识库行点「去上传」：

1. 页面跳转到 `/`（首页上传页）
2. 表单中 `tenant_id`、`kb_id` 已自动填好，无需手动输入

从知识库行点「去检索」：

1. 页面跳转到 `/retrieve`
2. 表单中 `tenant_id`、`kb_id` 已自动预填

### 5. 复制 kb_id

点击知识库行的复制按钮，粘贴到文本编辑器，确认内容是完整的 `kb_id`（不是截断显示的那段）。

## 检索调试页测试

### 1. 从列表页跳转预填

从列表页跳转后，`tenant_id` 和 `kb_id` 已预填在检索配置区的检索范围框里，不需要手动输入。

### 2. 基本检索

填入有效的 `tenant_id`、`kb_id`、`query`，点「检索」：

1. 召回结果列表正常渲染，每条 chunk 显示 score、title、document_id、chunk_id
2. content 默认折叠，点击可展开

### 3. 检索模式切换

1. 默认 `hybrid` 模式：检索模式控件下方显示 `vector_top_k`、`bm25_top_k`、`rrf_k` 三个输入框，在同一行
2. 切换到 `vector`：hybrid 子参数行消失
3. 切换到 `bm25`：hybrid 子参数行消失
4. 切回 `hybrid`：子参数行重新出现，且默认值 20/20/60 未丢失

### 4. rerank 开关

1. 未勾选 rerank：发出的请求体中不含 `rerank_options` 字段
2. 勾选 rerank：`rerank top_n` 输入框显示，请求体带上 `rerank_options`
3. 勾选 rerank 后召回结果中每条 chunk 显示 `rerank_score`

### 5. 运行摘要

检索完成后，运行摘要 Card 显示：

1. `latency_ms` 为服务端耗时（数值由后端返回，不是前端计时），标注单位 ms
2. 当前检索模式、召回数量
3. 若启用 rerank，显示 provider 和模型名

服务端耗时字段验证：在 Network 面板查看响应体，确认 `metadata.latency_ms` 字段存在且为整数。
