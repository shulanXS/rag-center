# Retrieve 兜底与降级测试验收

## 测试准备

后端已启动，Celery Worker 运行中。准备 standard 档 Key（hybrid 可用）和至少两个知识库，各上传若干文档并索引成功。

快速确认环境正常：

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/retrieve \
  -H "Authorization: Bearer rk_live_你的key" \
  -H "Content-Type: application/json" \
  -d '{"kb_id":"KB_ID","user_id":"u1","query":"测试","profile":"balanced"}'
```

预期：`code=0`，有 chunk，无 degraded。确认基线正常后再进行以下测试。

pytest tests/test_retrieve_robustness.py -v

## Hybrid 降级测试

### 1. BM25 不可用时，降为纯 vector

停掉 Elasticsearch：

```bash
docker compose stop elasticsearch
```

用 balanced profile 发起检索：

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/retrieve \
  -H "Authorization: Bearer rk_live_你的key" \
  -H "Content-Type: application/json" \
  -d '{"kb_id":"KB_ID","user_id":"u1","query":"退款时限","profile":"balanced"}'
```

预期：

1. `code=0`，仍有 chunk（纯 vector 召回）
2. `metadata.retrieval.degraded=true`
3. `degraded_reason` 含 bm25 或 keyword 相关说明

恢复 ES：

```bash
docker compose start elasticsearch
```

### 2. 验证脚本

```bash
python scripts/verify_robustness_retrieve.py
```

预期：各 case 输出 OK 或 SKIP（无 ES 环境时说明原因），不出现未捕获异常。

### 3. 双路都失败时拒绝请求

此场景通过单测验证（mock vector + BM25 同时失败）：

预期：`code` 为 RETRIEVAL_FAILED 对应错误码，不返回 200。

### 4. 单模式失败时拒绝，不降级

停掉 Elasticsearch，改用 bm25 模式（如 custom + mode=bm25）：

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/rag/retrieve \
  -H "Authorization: Bearer rk_live_你的key" \
  -H "Content-Type: application/json" \
  -d '{
    "kb_id":"KB_ID","user_id":"u1","query":"退款时限",
    "profile":"custom",
    "retrieval_options":{"mode":"bm25"}
  }'
```

预期：`code` 非 0，直接拒绝，不降级为 vector。

恢复 ES。
