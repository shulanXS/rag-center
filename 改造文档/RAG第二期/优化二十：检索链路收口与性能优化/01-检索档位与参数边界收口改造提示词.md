# 检索档位与参数边界收口改造提示词

点击此处可复制本篇提示词

在当前 rag-center 项目中，收口 `speed`、`balanced`、`quality` 和 `custom` 四种检索档位。三个命名档位必须成为后端固定契约，不再被请求中的高级参数覆盖；只有 `custom` 允许调用方调整公开的检索参数。

统一三个命名档位的最终返回数量为 5/10/10，修复 quality 声明 Top8、精排默认只返回 Top5 的不一致。保留已经验证有效的 Query Rewrite 产品行为，同义词扩展继续默认关闭。

修改前先检查当前代码，以实际目录、Schema 和调用关系为准。重点检查 `app/tenant/retrieve_presets.py`、`app/tenant/retrieve_policy.py`、`app/schemas/rag.py`、`app/services/rag_service.py` 和检索调试页面，不重复创建已有配置模型。

## 一、改造目标

- `speed` 最终固定返回 Top5；
- `balanced` 最终固定返回 Top10；
- `quality` 使用共同候选 Top20，Qwen3 精排后固定返回 Top10；
- 命名档位不允许覆盖 `top_k`、检索模式、召回数量、精排、Evidence 和 Query 处理参数；
- `custom` 保留必要的高级配置能力；
- RRF 公式和 `rrf_k` 由服务端固定，不作为普通请求调优参数；
- 同义词扩展在所有命名档位中显式关闭；
- quality 继续开启 Query Rewrite，不改变其检索查询使用方式；
- 响应 metadata 展示真实生效配置；
- 前端命名档位只提交档位名称，不提交隐藏的覆盖参数；
- 评测配置与生产档位使用同一份后端预设来源，避免复制两套数值。

## 二、固定档位定义

将预设统一为：

| 档位 | 查询处理 | 召回 | 精排 | 最终返回 |
|------|----------|------|------|---------:|
| speed | Rewrite 关闭、同义词关闭 | Vector Top10 | 关闭 | Top5 |
| balanced | Rewrite 关闭、同义词关闭 | Vector Top10 + BM25 Top10 + RRF | 关闭 | Top10 |
| quality | Rewrite 开启、同义词关闭 | Vector Top20 + BM25 Top20 + RRF | Qwen3 Top10 | Top10 |

`speed` 的 Vector Top10 是候选召回数量，Top5 是最终返回数量。这样既保持轻量档位，又给过滤和降级留出少量候选空间。

`quality` 必须显式写出：

```python
top_k = 10
rerank_options = {
    "enabled": True,
    "top_n": 10,
}
```

不能继续依赖 `DEFAULT_RERANK_TOP_N = 5`。精排通用默认值也应改成“未指定时跟随最终 `top_k`”，但命名档位仍要保存显式 `top_n`，使配置一眼可见。

RRF 固定使用：

```text
fusion = rrf
rrf_k = 60
```

`hybrid_fusion` 不再表现为可选择多种算法的产品配置。当前只有 RRF 实现时，metadata 只能报告真实执行的 `rrf`，不能把未实现的配置值原样回显成另一种融合算法。

## 三、命名档位参数边界

当 `profile` 为 `speed`、`balanced` 或 `quality` 时，请求只能携带检索范围和通用请求信息：

```text
query
user_id
kb_id / kb_ids
profile
index_version
observability_enabled
```

以下字段只要由命名档位请求显式传入，就返回参数错误，不再静默合并：

```text
top_k
retrieval_options
rerank_options
evidence_options
query_options
```

错误示例：

```json
{
  "code": "PARAM_ERROR",
  "msg": "命名检索档位不允许覆盖高级参数，请使用 custom",
  "data": {
    "profile": "balanced",
    "conflicting_fields": ["top_k", "rerank_options"]
  }
}
```

即使调用方传入的值刚好与预设相同，也应拒绝。否则客户端会继续误以为这些字段对命名档位有效，后续配置调整时又会产生歧义。

`index_version` 属于检索数据范围，不属于档位质量参数，可以继续显式指定。知识库权限、套餐限制和最多知识库数量也继续由现有策略校验。

## 四、custom 可配置范围

`custom` 允许调用方显式指定：

- 最终 `top_k`；
- `vector`、`bm25` 或 `hybrid` 模式；
- `vector_top_k` 和 `bm25_top_k`；
- 是否启用 Qwen3 精排及 `top_n`；
- 是否启用 Evidence 及其公开预算；
- 是否启用 Query Rewrite；
- 是否启用同义词扩展。

`custom` 仍然受套餐能力上限、Schema 数值范围和服务端安全上限约束。调用方不能配置：

- RRF 之外的融合公式；
- `rrf_k`；
- 精排 Provider 或模型名称；
- Embedding Provider 或模型名称；
- 超时、重试、连接池和并发数；
- 租户无权访问的知识库或索引版本。

为了兼容已有客户端，可以分两步移除公开 `rrf_k`：

1. 服务端先忽略并记录弃用告警，但 metadata 始终返回固定值 60；
2. 更新前端和 SDK 后，从公开 Schema 删除该字段。

如果项目当前没有正式 SDK 和向后兼容承诺，可以直接删除，并同步修改测试与调试台。

## 五、策略解析实现

修改：

```text
app/tenant/retrieve_presets.py
app/tenant/retrieve_policy.py
app/schemas/rag.py
```

推荐把命名档位解析改为完整替换，而不是“预设与请求合并”：

```python
if profile == "custom":
    resolved = resolve_custom_request(request, plan_context)
else:
    reject_named_profile_overrides(request)
    resolved = build_named_profile_request(
        request=request,
        preset=RETRIEVE_PROFILE_PRESETS[profile],
    )
```

删除命名档位路径中的以下逻辑：

```python
top_k = request.top_k or preset.top_k
merged = {**preset, **request_override}
```

不要通过 `or` 选择数值，因为它会掩盖请求是否显式提交了覆盖字段。冲突检查应基于字段是否为 `None` 或 `model_fields_set`，再由预设一次性构造实际请求。

套餐策略只负责判断档位和能力是否允许，不能把固定档位悄悄改成另一条链路。部署级紧急开关可以临时关闭外部模型能力，但必须在 metadata 中明确记录 `disabled_by_system` 或 degraded 原因，不能继续把实际未执行的能力报告为已启用。

## 六、精排返回数量修复

修改 `app/services/rag_service.py` 中精排数量解析：

```python
requested_top_n = (
    request.rerank_options.top_n
    if request.rerank_options and request.rerank_options.top_n is not None
    else top_k
)
top_n = min(requested_top_n, top_k, len(chunks))
```

要求：

- quality 有 20 条候选时，Qwen3 收到 20 条并返回 10 条；
- 候选不足 10 条时返回实际候选数量；
- 精排失败时按 RRF 原顺序降级返回最多 10 条；
- 未开启精排时按档位最终 `top_k` 截取；
- metadata 的 `candidate_count`、`top_n` 和 `returned_count` 使用实际值。

不要把共同候选 Top20 与最终 Top10 混成同一个字段。候选数量属于召回和精排输入，最终数量属于接口响应契约。

## 七、有效配置 metadata

扩展现有租户策略或检索 metadata，至少能够清楚表达：

```json
{
  "profile": "quality",
  "top_k": 10,
  "retrieval": {
    "mode": "hybrid",
    "vector_top_k": 20,
    "bm25_top_k": 20,
    "fusion": "rrf",
    "rrf_k": 60
  },
  "query": {
    "rewrite_enabled": true,
    "synonym_enabled": false
  },
  "rerank": {
    "enabled": true,
    "provider": "qwen3",
    "top_n": 10
  }
}
```

metadata 只记录真实执行结果，不直接复制原请求。发生全局开关降级、Provider 异常或候选不足时，必须同时记录实际状态和降级原因。

## 八、统一评测配置来源

为统一运行器增加命名档位解析能力。评测配置使用：

```json
{
  "profile": "speed",
  "index_version": "v2"
}
```

运行器应从生产预设解析出完整有效配置并写入 `experiment.snapshot.json`，不要在评测 JSON 中再次手写 speed、balanced、quality 的 TopK 和召回数量。

只有消融实验和固定性能实验使用 `custom`，因为这些实验必须精确锁定单一变量。正式三档回归使用命名档位，验证的就是生产实际配置。

## 九、前端调整

修改检索调试页面：

- 选择 speed、balanced 或 quality 时隐藏或只读展示高级参数；
- 请求体不提交 `top_k` 和各类 options；
- 页面从响应 metadata 展示真实生效配置；
- 选择 custom 时显示允许开放的高级参数；
- 移除 `hybrid_fusion`、`rrf_k` 和精排 Provider 选择；
- custom 的同义词扩展使用显式开关，默认关闭；
- quality 清楚展示“共同候选 20，Qwen3 精排返回 10”，避免只显示一个含义不清的 TopK。

前端隐藏参数不能代替后端校验。直接调用 API 时也必须执行相同边界。

## 十、自动化测试

后端至少覆盖：

- speed 解析为 Vector Top10、最终 Top5；
- balanced 解析为 Hybrid 10+10、最终 Top10；
- quality 解析为 Rewrite + Hybrid 20+20 + Qwen3 Top10；
- 三个命名档位都显式关闭同义词扩展；
- quality 精排成功返回 10 条，不再默认 Top5；
- quality 精排失败按 RRF 顺序返回 Top10；
- 候选不足 10 条时返回实际数量；
- 命名档位携带任一高级覆盖字段时返回参数错误；
- custom 的允许参数可以生效，并继续受套餐与数值上限约束；
- RRF 固定为 `rrf_k=60`，请求不能改变；
- metadata 与实际执行配置一致；
- v1 和 v2 都能显式指定索引版本；
- Query Rewrite 行为保持不变；
- 同义词扩展默认关闭。

前端至少覆盖：

- 命名档位请求体不包含高级 options；
- custom 请求体只包含用户明确选择的参数；
- quality 页面显示候选 20、最终 10；
- 页面展示的生效参数来自响应 metadata。

单元测试使用 Fake Provider 或 mock，不调用真实 Embedding、LLM、Elasticsearch 和 Qwen3 服务。

## 十一、验收标准

- speed、balanced、quality 的最终返回数量稳定为 5/10/10；
- quality 不再出现“配置 Top8、实际 Top5”；
- 同名档位在 API、前端、日志和评测报告中代表同一条链路；
- 只有 custom 能调整公开高级参数；
- 普通调用方不能修改 RRF 公式和 `rrf_k`；
- Query Rewrite 保持现有行为，同义词扩展保持默认关闭；
- 评测快照能够记录每次运行的完整有效配置；
- 所有相关单元测试和接口回归通过。
