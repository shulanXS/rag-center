# 混合检索并行与外部连接复用改造提示词

点击此处可复制本篇提示词

在当前 rag-center 项目中，将 Hybrid 的向量召回分支和 BM25 召回分支改为受控并行执行，并让 Embedding、LLM、Qwen3 精排和 Elasticsearch 复用应用生命周期内的 HTTP 连接池。

改造只优化执行方式，不改变查询文本、召回数量、RRF 公式、精排算法、索引内容和结果契约。并行前后相同固定配置应得到相同候选与排序；外部服务异常时继续沿用现有降级行为。

修改前先检查当前代码，以实际目录和依赖关系为准。重点检查 `app/main.py`、`app/api/v1/routes/rag.py`、`app/services/rag_service.py`、Embedding、LLM、Qwen3、Elasticsearch Provider 以及异步测试。

## 一、改造目标

- Hybrid 的向量召回和 BM25 召回同时启动；
- Hybrid 阶段耗时按墙钟时间统计；
- 单路失败不取消另一条已经运行的分支；
- 两路都失败时返回标准检索错误；
- 不在线上请求中反复创建和关闭 `httpx.AsyncClient`；
- 模型服务与 Elasticsearch 使用独立的共享连接池；
- Provider 通过依赖注入使用共享客户端；
- 应用关闭时可靠关闭连接池；
- 测试和脚本可以注入 `MockTransport` 或 Fake Client；
- 不跨事件循环、进程或 Worker 共享 `AsyncClient`；
- metadata 记录两条分支和完整 Hybrid 阶段的真实耗时；
- 性能对比使用冻结请求，不借修改配置制造提升。

## 二、Hybrid 并行执行方式

当前顺序是先等待向量分支全部完成，再调用 BM25。改为：

```python
async def run_vector_branch() -> BranchResult:
    try:
        chunks = await vector_search(...)
        return BranchResult.success("vector", chunks)
    except Exception as exc:
        return BranchResult.failure("vector", exc)


async def run_bm25_branch() -> BranchResult:
    try:
        chunks = await bm25_search(...)
        return BranchResult.success("bm25", chunks)
    except Exception as exc:
        return BranchResult.failure("bm25", exc)


vector_result, bm25_result = await asyncio.gather(
    run_vector_branch(),
    run_bm25_branch(),
)
```

向量分支内部仍然是：

```text
Embedding → pgvector 相似度查询
```

BM25 不依赖 Embedding，因此可以在 Embedding 网络请求开始时同步启动。不要把 `embed_query()` 放在 `gather()` 之前，否则 BM25 仍然要等待 Embedding 完成，无法获得完整并行收益。

全局多知识库 Hybrid 使用同样的两分支结构：向量分支只计算一次 Embedding，并查询整个版本化知识库范围；BM25 分支查询相同范围。

## 三、分支结果与降级语义

不要让 `asyncio.gather()` 的第一个异常直接取消另一条分支。每个分支在内部捕获可预期异常并返回结构化结果：

```python
@dataclass(slots=True)
class RetrievalBranchResult:
    source: Literal["vector", "bm25"]
    chunks: list[dict]
    latency_ms: int
    error: Exception | None = None
```

合并规则：

| Vector | BM25 | 结果 |
|--------|------|------|
| 成功 | 成功 | 执行 RRF |
| 失败 | 成功 | 返回 BM25 顺序，`degraded=true` |
| 成功 | 失败 | 返回 Vector 顺序，`degraded=true` |
| 失败 | 失败 | 抛出 `RETRIEVAL_FAILED` |

取消请求时要向两个子任务传播取消信号，不要把 `CancelledError` 当成普通分支失败后继续做无效工作。超时由已有外层预算或 Provider 超时控制，本轮不新增多层重试。

同步 SQLAlchemy Session 仍由当前请求持有。BM25 是独立 HTTP 调用，可以和向量分支并发；不要把同一个同步 Session 交给多个线程，也不要为了并行强行增加线程池。

## 四、耗时记录

每条分支分别记录墙钟耗时：

```text
vector_latency_ms
  ├─ embedding_latency_ms
  └─ vector_store_latency_ms

bm25_latency_ms

hybrid_latency_ms
```

`hybrid_latency_ms` 从两条任务启动前开始，到两条任务都结束且 RRF 完成为止，不能使用：

```text
vector_latency_ms + bm25_latency_ms
```

并行链路中各分支耗时之和通常大于端到端耗时，这是正常现象。接口总耗时继续由最外层检索入口统一统计，不能把 Query Rewrite、精排、上下文扩展或响应序列化遗漏后仍命名为“接口总耗时”。

## 五、共享 HTTP 客户端容器

新增一个职责单一的应用级容器，例如：

```text
app/core/http_clients.py
```

建议模型：

```python
@dataclass(slots=True)
class ExternalHttpClients:
    model: httpx.AsyncClient
    elasticsearch: httpx.AsyncClient

    async def aclose(self) -> None:
        await asyncio.gather(
            self.model.aclose(),
            self.elasticsearch.aclose(),
        )
```

模型服务客户端可供 Embedding、OpenAI-Compatible LLM 和 Qwen3 精排复用。不同域名会在同一个客户端内部维护不同连接池；认证 Header 仍由每次 Provider 请求显式传入，不写进共享客户端默认 Header。

Elasticsearch 使用独立客户端，并保持 `trust_env=False`，防止系统代理意外影响内网检索。推荐显式配置：

```python
httpx.Limits(
    max_connections=100,
    max_keepalive_connections=20,
    keepalive_expiry=30.0,
)
```

具体数值允许通过部署级配置调整，但不进入 retrieve API，也不按租户配置。连接池大小需要结合 Worker 数量理解：每个进程各有一套连接池，不能把单进程上限误当成整套服务上限。

## 六、应用生命周期

将 FastAPI 应用改为 lifespan 管理：

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    clients = build_external_http_clients()
    app.state.external_http_clients = clients
    try:
        yield
    finally:
        await clients.aclose()


app = FastAPI(
    title="RAG Center",
    version="0.1.0",
    lifespan=lifespan,
)
```

通过 FastAPI Dependency 从 `app.state` 获取客户端容器，再注入 `RagService` 和 `ResearchService`。不要在业务服务中直接导入一个模块级可变单例。

HTTP Provider 的构造方式调整为：

```python
class OpenAICompatibleEmbeddingProvider:
    def __init__(self, *, client: httpx.AsyncClient, ...):
        self.client = client
```

Provider 的单次方法只发请求：

```python
response = await self.client.post(
    url,
    json=payload,
    headers=request_headers,
    timeout=self.timeout,
)
```

不能再使用：

```python
async with httpx.AsyncClient(...) as client:
    ...
```

被注入的共享客户端由应用拥有，Provider 不能在请求结束时关闭它。

## 七、需要接入共享客户端的组件

至少调整在线检索会调用的组件：

```text
OpenAICompatibleEmbeddingProvider
OpenAICompatibleLLMProvider
Qwen3RerankProvider
ElasticsearchKeywordSearchProvider
RagService
ResearchService
```

`RagService(db)` 当前在每次 API 请求中创建 Provider。可以继续按请求创建轻量 Provider 对象，但 Provider 必须持有应用级共享客户端，不能创建新的连接池。

离线评测如果通过 HTTP 请求访问已启动服务，会自然使用服务端连接池。直接在进程内构造 Provider 的脚本和测试，应显式创建并关闭自己的客户端，或使用测试 fixture 管理生命周期。

异步任务 Worker 不能使用 FastAPI 进程的客户端对象。索引任务如果也要复用连接，应在 Worker 进程和事件循环内创建自己的客户端容器，并在 Worker 关闭时释放。

## 八、超时、认证和安全边界

连接池复用不能改变现有安全语义：

- API Key 和 Authorization Header 每次请求构造；
- 不把某个租户的 Header 保存到共享客户端默认配置；
- 不缓存请求正文、查询文本和候选内容；
- Embedding、LLM、精排和 Elasticsearch 保留各自的请求超时；
- 日志继续脱敏 API Key 和完整候选正文；
- HTTP 401、429、5xx、超时和非法响应仍转换为现有 Provider 异常；
- 不因为连接复用自动增加重试，避免重复模型费用和不可控尾延迟。

如果共享客户端已经关闭，新的请求应快速失败并记录明确错误，不能悄悄创建临时客户端绕过生命周期管理。

## 九、测试可注入性

现有 Provider 测试如果通过替换全局 `httpx.AsyncClient` 注入 `MockTransport`，应改成显式注入：

```python
transport = httpx.MockTransport(handler)
client = httpx.AsyncClient(transport=transport)
provider = Qwen3RerankProvider(client=client)
```

测试 fixture 负责 `await client.aclose()`。这种方式能直接验证 Provider 是否使用传入客户端，也不会因为实现不再临时构造 Client 而让测试失效。

## 十、自动化测试

并行检索至少覆盖：

- Vector 与 BM25 确实在彼此完成前启动；
- 两条分支成功时使用相同查询范围并正常 RRF；
- 并行前后固定候选的 Chunk ID 和排序一致；
- Vector 失败时保留 BM25；
- BM25 失败时保留 Vector；
- 两路都失败时返回标准错误；
- 请求取消时两个任务都停止；
- `hybrid_latency_ms` 是墙钟耗时，不是分支耗时相加；
- 单库和双库都复用同一并行实现。

连接复用至少覆盖：

- 应用启动只创建一组客户端容器；
- 连续多个 retrieve 请求复用同一个客户端实例；
- Embedding、LLM 和 Qwen3 使用模型服务客户端；
- BM25 使用 Elasticsearch 客户端；
- Provider 不关闭注入客户端；
- 应用关闭后每个客户端只关闭一次；
- 一个客户端请求失败不会导致连接池对象被替换；
- Header 按请求生成，不发生租户或凭证串用；
- `MockTransport` 可以完成 Provider 单元测试；
- 多 Worker 场景不会跨进程或跨事件循环共享客户端。

所有自动化测试使用 Fake Provider、事件控制器或 `MockTransport`，不依赖真实网络延迟。

## 十一、本轮不包含的性能改动

- 不修改 Langfuse 每次请求的刷新策略；
- 不修改 HTTP 中间件的响应正文日志策略；
- 不修改图候选注入和上下文扩展触发条件；
- 不调整数据库 HNSW 索引和分区；
- 不增加缓存、批处理、自动重试或熔断框架；
- 不改变模型、Prompt、召回数量和精排数量。

这些变量保持不变，才能使用冻结基线判断并行与连接复用本身是否带来收益。

## 十二、验收标准

- Hybrid 的 Vector 和 BM25 分支受控并行执行；
- 单路异常时安全降级，两路异常时标准失败；
- 在线请求路径中不再临时创建 Embedding、LLM、Qwen3 和 Elasticsearch 的 `AsyncClient`；
- 共享连接池在应用启动时创建、关闭时释放；
- Provider 不持有跨请求业务状态；
- 并行前后固定输入的候选和排序一致；
- metadata 能区分分支耗时和完整 Hybrid 耗时；
- 固定单库性能测试的失败率为 0，质量不下降，P50/P95 有可复现的对比结果。
