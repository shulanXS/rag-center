## 一、验收要回答的问题

| 测试 | 需要回答的问题 |
|------|----------------|
| 工程正确性 | 档位、并行、连接生命周期、权限过滤和降级是否符合契约 |
| 单库固定配置 | 并行与连接复用是否降低同一条 v2 Hybrid 链路的 P50/P95 |
| 1 库/2 库测试 | 多库是否只计算一次 Embedding，并摆脱强制平均分配 |

| v1/v2 汇总 | 第二期完整链路相对第一期冻结档位取得了什么整体变化 |

单库性能测试不混入多知识库；多知识库只测 1 个和 2 个知识库，不扩展到 5 库压力测试。

## 五、接口冒烟

正式评测前只执行少量请求，确认环境和契约正确。

### 1. 三个命名档位

每个档位各执行 1 道题，检查：

| 档位 | 必须看到的结果 |
|------|----------------|
| speed | v2、Vector Top10、最终不超过 5、Rewrite/同义词/精排关闭 |
| balanced | v2、Hybrid 10+10、RRF 60、最终不超过 5、精排关闭 |
| quality | v2、Rewrite 开启、同义词关闭、Hybrid 20+20、Qwen3 Top5，精排 query 与 Rewrite Query 一致 |

再构造一个 `profile=balanced` 且携带 `top_k` 或 `rerank_options` 的请求，必须返回明确参数错误。

### 2. 单库 Hybrid

检查：

- Vector 和 BM25 两条分支都成功；
- `fusion_scope=global`；
- Embedding、Vector、BM25 请求数各为 1；
- 返回 Top10；
- 没有调用 Query Rewrite、同义词、Qwen3 和 Evidence。

### 3. 双库 Hybrid

检查：

- 两个知识库都在授权范围内；
- Embedding 仍然只调用 1 次；
- Vector Top20 和 BM25 Top20 是双库合计数量；
- 交换 `kb_ids` 顺序后 Chunk ID 与排序不变；
- 来源分布由相关性决定，没有每库保底配置。

冒烟失败时停止正式模型调用，先修复配置或实现。

## 六、单知识库固定配置对比

这项测试只验证单库 Hybrid 并行和连接复用，不使用命名档位，也不引入多库、Query Rewrite、同义词、精排或 Evidence。

改造后的请求必须与冻结 v2 配置完全相同：

```json
{
  "profile": "custom",
  "top_k": 10,
  "index_version": "v2",
  "retrieval_options": {
    "mode": "hybrid",
    "vector_top_k": 20,
    "bm25_top_k": 20
  },
  "rerank_options": {"enabled": false},
  "evidence_options": {"enabled": false},
  "query_options": {
    "enabled": false,
    "strategy": "noop",
    "synonym_enabled": false
  },
  "observability_enabled": false
}
```

RRF k 虽然不再由请求提交，但有效配置必须仍为 60，并写入快照。

统一运行器应支持“冻结结果作为 baseline，只在线调用 candidate”的运行方式，例如：

```text
baseline_run_dir:
  eval/results/20260825_034128_199038_opt20_single_kb_performance_baseline_pre_opt20
baseline_group: candidate
candidate: 当前 v2 固定配置
```

运行器直接读取冻结 baseline 的 raw、metrics 和 manifest，不向旧链路重新发请求。新的结果目录仍包含标准快照、candidate raw、metrics、comparison 和 report。

验收口径：

| 项目 | 要求 |
|------|------|
| 请求失败 | 0/20 |
| 返回数量 | 每题最多 10，正常有足够候选时为 10 |
| 索引版本 | 所有 Chunk 都是 v2 |
| Context Precision | 相对 0.9087 不下降超过 0.02 |
| Context Recall | 相对 0.9500 不下降超过 0.02 |
| 应用模型调用 | 只有一次 Embedding，不增加 LLM/Qwen3 调用 |
| P50/P95 | 与 1664.8ms / 2538.9ms 做同条件对比 |

性能结论按实际数据写：

- P50、P95 都下降，才能表述为“典型延迟和尾延迟均有改善”；
- 只有一项下降时，只报告对应指标；
- P95 上升不超过 5% 可以判定为无明显回退，但不能写成性能提升；
- P95 上升超过 5% 时暂停通过，先排查连接池、并发、外部服务和运行环境；
- 不能用代码已经并行作为性能改善的替代证据。

## 七、1 库/2 库全局融合对比

继续使用：

```text
eval/datasets/opt20_multi_kb_baseline.json
```

固定请求保持 v1、Custom、Hybrid 20+20、Top10，关闭 Rewrite、同义词、精排与 Evidence。RRF 使用服务端固定值 60。

先运行 4 道质量题，再执行性能脚本：

```bash
python scripts/benchmark_multi_kb_retrieval.py \
  --dataset eval/datasets/opt20_multi_kb_baseline.json \
  --request-config eval/configs/opt20_multi_kb_after.json \
  --tenant-id <评测租户ID> \
  --repeat 10 \
  --warmup 1 \
  --output eval/results/<日期>_opt20_multi_kb_after_performance.json
```

`opt20_multi_kb_after.json` 与冻结配置只允许有一个接口层变化：不再提交公开 `rrf_k`，但快照中的有效 `rrf_k` 必须仍为 60。不得改变题目、KB ID、索引版本、召回数和功能开关。

质量与正确性要求：

| 项目 | 要求 |
|------|------|
| 1 库题 | 正常返回授权范围内结果 |
| 2 库题 | Context Recall 不低于冻结值 1.0000 |
| 2 库 Precision | 应高于冻结值 0.3431，否则不能证明全局融合带来质量收益 |
| Embedding 请求 | 1 库为 1 次，2 库仍为 1 次 |
| Vector/BM25 请求 | 正常 Hybrid 各 1 次 |
| 顺序稳定性 | 交换 `kb_ids` 后结果一致 |
| 权限 | 不出现范围外 Chunk |
| 失败 | 1 库和 2 库正式样本都为 0 |

不要求每个真实请求都必须是非 5+5，因为全局相关性也可能自然产生 5+5。是否取消平均分配由确定性单元测试、`fusion_scope=global`、一次全局召回和顺序不变共同证明。正式报告额外展示来源分布；如果所有双库真实样本仍然都是 5+5，需要检查数据相关性和实现，但不能只凭数量直接下结论。

性能继续展示 1 库和 2 库各自的平均、P50、P95、最大值和失败数。1 库与 2 库的横向差异用于说明知识库范围扩大后的成本；每种范围还要分别与自身改造前数值比较，不能用“2 库比 1 库慢”代替改造前后对比。

正式指标只使用：

| 指标 | 作用 |
|------|------|

- Speed 正常候选充足时返回 5 条；
- Balanced 正常候选充足时返回 5 条；
- Quality 正常候选充足时返回 5 条；
- Quality 的 Qwen3 `top_n=5`，使用严格中文 instruct 和 Rewrite Query；
- 三档同义词扩展都关闭；
- Quality 保持 Query Rewrite；
- 所有结果都是 v2；
- 20 道题请求失败为 0；
- metadata 与命名档位契约一致。
