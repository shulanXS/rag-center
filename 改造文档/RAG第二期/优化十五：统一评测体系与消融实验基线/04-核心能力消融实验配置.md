# 核心能力消融实验配置

点击此处可复制本篇提示词

在当前 rag-center 项目中，为已经具备的检索能力建立标准消融实验配置。每个实验只比较 `baseline` 和 `candidate`，只改变一个目标能力，并使用同一批问题、同一知识库语料和同一组非实验参数。

配置的目标不是一次跑出尽可能多的组合，而是让每份报告都能清楚回答一个问题：开启或替换某项能力后，质量提升了多少，增加了多少延迟和模型调用，是否值得启用。

## 一、统一实验规则

所有基础检索实验默认使用：

```text
dataset：eval/datasets/golden_basic_20.json
suite：basic
题目：20 道电商基础题
索引：使用项目当前默认方式构建的知识库
正式次数：每题每组 1 次
warm-up：每组 2 次
业务请求并发数：4
RAGAS 并发数：4
RAGAS 遥测：关闭
离线 Langfuse：关闭
```

每个实验配置必须声明：

```json
{
  "experiment_id": "唯一实验ID",
  "target": "本次验证的能力",
  "changed_fields": ["允许发生变化的配置路径"],
  "primary_metric": "主指标",
  "baseline": {},
  "candidate": {},
  "decision": {}
}
```

运行器展开两组最终生效配置后，只有 `changed_fields` 中声明的字段可以不同。存在未声明差异时直接拒绝运行。

## 二、固定不变的条件

以下条件在所有实验中保持一致：

- Golden Set 版本
- 知识库语料版本
- 知识库 ID 和已建索引内容
- Embedding 模型
- 生成模型
- RAGAS Judge 模型
- TopK、候选数量和超时
- 租户、套餐权限和 API Key
- 运行机器、服务实例和并发数
- warm-up 数量

重排实验必须冻结相同的初始候选集。

## 三、Query Rewrite 消融

实验问题：

> 开启 Query Rewrite 后，口语化问题和文档表达不一致的问题是否更容易召回正确内容？

新增：

```text
eval/experiments/query_rewrite.json
```

唯一差异：

| 配置 | baseline | candidate |
|------|----------|-----------|
| `query_options.rewrite_enabled` | `false` | `true` |

冻结：

```text
synonym_enabled=false
retrieval_mode=vector
rerank_enabled=false
top_k=10
```

主指标使用 `context_recall`，重点查看 `paraphrase` 题型。建议门槛：

```json
{
  "min_primary_improvement": 0.03,
  "quality_guardrails": {
    "context_precision": {
      "min_delta": -0.02
    }
  },
  "cost_limits": {
    "max_p95_increase_ratio": 0.40,
    "max_model_calls_increase": 1.0
  }
}
```

报告需要说明改写带来的实际召回收益是否足以覆盖额外的一次模型调用。

## 四、同义词扩展消融

实验问题：

> 只开启知识库同义词扩展，是否能改善简称、俗称和业务术语的召回？

新增：

```text
eval/experiments/synonym_expansion.json
```

唯一差异：

| 配置 | baseline | candidate |
|------|----------|-----------|
| `query_options.synonym_enabled` | `false` | `true` |

冻结：

```text
rewrite_enabled=false
retrieval_mode=vector
rerank_enabled=false
top_k=10
```

主指标使用 `context_recall`，重点查看带有同义词标签的题目。报告额外展示：

- 同义词扩展触发题数
- 实际命中的扩展词
- 无效扩展导致 Precision 下降的题目

同义词扩展不调用 LLM，平均应用模型调用数不应增加。

## 五、Hybrid Search 消融

实验问题：

> 在向量检索基础上增加 BM25 和 RRF，是否提高了整体召回，同时没有引入过多无关内容？

新增：

```text
eval/experiments/hybrid_search.json
```

唯一差异：

| 配置 | baseline | candidate |
|------|----------|-----------|
| `retrieval_options.mode` | `vector` | `hybrid` |

candidate 固定使用：

```text
Vector + BM25 + RRF
vector_top_k=10
bm25_top_k=5
rrf_k=10
```

BM25 使用章节路径、正文和标题进行跨字段匹配，至少命中一半查询词才进入候选集，避免常见口语词带来大量弱相关结果。

冻结：

```text
rewrite_enabled=false
synonym_enabled=false
rerank_enabled=false
final_top_k=10
```

主指标使用 `context_recall`，Context Precision 作为质量护栏，不增加其他正式指标。

如果需要了解 BM25 单路能力，另建 `bm25_vs_vector.json`，使用 `vector` 和 `bm25` 两组，不在 Hybrid 实验中增加第三组。

## 六、精排升级实验

实验问题：

> 在完全相同的召回候选上，Qwen3-Rerank 是否比原有 LLM 重排更准确、更高效？

新增：

```text
eval/experiments/rerank_upgrade.json
```

唯一差异：

| 配置 | baseline | candidate |
|------|----------|-----------|
| 精排模型 | 原有 LLM 重排 | Qwen3-Rerank |

冻结：

```text
retrieval_mode=hybrid
candidate_k=20
final_top_k=10
rewrite_enabled=false
synonym_enabled=false
```

两组必须使用同一份初始 Top20 候选，分别精排后返回 Top10。统一运行器每道题只生成一次候选，再交给两种模型，不能分别发起两次可能波动的召回。

主要观察 Context Precision，Context Recall 不能下降。报告只输出四个公共指标，并说明质量变化、P95 和模型调用成本。

## 七、Profile 整体验收

Profile 是多项能力的组合，不用于归因单个组件。使用两个独立配置完成套餐对比：

```text
eval/experiments/profile_speed_vs_balanced.json
eval/experiments/profile_balanced_vs_quality.json
```

对比关系：

| 实验 | baseline | candidate |
|------|----------|-----------|
| 速度与均衡 | `speed` | `balanced` |
| 均衡与质量 | `balanced` | `quality` |

Profile 报告重点回答：

- balanced 是否比 speed 获得更好的召回
- quality 是否比 balanced 获得进一步质量收益
- 三种配置的 P95 和模型调用数是否符合产品定位
- 哪种 Profile 适合作为默认值

由于 Profile 会同时改变多项配置，报告必须标记为“组合能力验收”，不能声称收益来自某一个开关。

## 八、多知识库实验

只有 Golden Set 中存在真实跨知识库题时才创建：

```text
eval/experiments/multi_kb_retrieval.json
```

对比关系：

| 配置 | baseline | candidate |
|------|----------|-----------|
| 检索范围 | 只检索一个主知识库 | 检索题目指定的全部目标知识库 |

使用 `multi_kb` suite，不混入只需要单库回答的普通题。主指标使用 `context_recall`，并额外输出各知识库的证据覆盖情况。

没有合适的跨库语料和问题时，将该实验标记为 `NOT_READY`，不要用电商与人事的无关问题拼成跨库题。

## 九、推荐执行顺序

基础检索按以下顺序执行：

```text
Hybrid Search
精排升级
Query Rewrite
同义词扩展
Profile 整体验收
```

该顺序与能力引入顺序一致。Hybrid Search 首先在改写、同义词和重排全部关闭的条件下，与纯向量检索比较；后续实验使用当时已经验收通过的检索链路作为共同底座，并且每次仍然只改变一个目标字段。每个实验都要从自己的配置完整生成 `baseline` 和 `candidate`。

多知识库实验只在对应 suite 和知识库准备完成后执行。

## 十、配置校验

运行任一实验前检查：

- 两组题目 ID 完全一致
- 两组题目数量一致
- 数据集、suite 和语料版本一致
- 实际差异没有超出 `changed_fields`
- 远程模型和知识库服务可用
- 需要固定候选的实验已生成候选快照
- 主指标所需的人工标注完整
- 验收门槛在运行前已经确定
- 输出目录不存在同名覆盖风险

校验失败时返回非 0 退出码，不发起正式模型调用。

## 十一、完成标准

- 每项核心能力都有独立的 baseline/candidate 配置
- 单功能实验只改变一个目标能力
- 20 道基础题在两组中完全一致
- 精排的两组能够复用相同 Top20 候选并返回 Top10
- Profile 使用两个独立的两组实验完成验收
- 多知识库只使用专门 suite
- 每个配置都包含主指标、门槛、护栏和允许差异字段
- 所有配置都能通过统一校验命令
- 每次运行都能生成带明确结论的独立报告
