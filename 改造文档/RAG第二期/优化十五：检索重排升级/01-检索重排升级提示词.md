# 检索重排升级提示词

点击此处可复制本篇提示词

在当前 rag-center 项目中，将通用 LLM 重排替换为阿里云百炼 `qwen3-rerank` 专用精排。复用现有 `RerankProvider`、retrieve API、套餐策略、rerank 开关和调试台，只替换后端重排实现，并增加可复现的 LLM 与 Qwen3-Rerank 数据对比。

修改前先检查当前代码，以实际目录、类型和调用关系为准，不要重复创建已有能力，也不要修改与重排无关的功能。

## 一、改造目标

- 新增 `Qwen3RerankProvider`，通过远程 API 调用百炼 `qwen3-rerank`
- 检索主链路固定使用 `Qwen3RerankProvider`，不增加 Provider 配置和模型选择入口
- 保持 `RerankProvider.rerank(query, chunks, top_n)` 接口不变
- 保留 `NoopRerankProvider`，用于关闭重排或套餐不支持重排的场景
- Qwen3-Rerank 调用失败时回退到 RRF/召回原顺序，不让整个 retrieve 失败
- 复用调试台已有的 rerank 开关、TopN、模型信息和分数展示
- 增加固定候选集对比工具，输出排序质量、时延、稳定性和退化案例
- 完成对比数据采集后删除 `LLMRerankProvider` 和 LLM 重排配置

## 二、固定对比候选集

新增数据集：

```text
eval/opt15_rerank/rerank_comparison.json
```

数据结构：

```json
{
  "name": "rerank_comparison_v1",
  "created_at": "实际生成时间",
  "profile": "balanced",
  "candidate_top_k": 20,
  "result_top_n": 5,
  "cases": [
    {
      "id": "refund_coupon_001",
      "question": "退款后优惠券会退回吗？",
      "kb_ids": ["实际知识库ID"],
      "candidates": [
        {
          "chunk_id": "实际chunk ID",
          "document_id": "实际document ID",
          "title": "优惠券规则",
          "content": "实际冻结的chunk正文",
          "score": 0.0312,
          "relevance": 3,
          "relevance_note": "直接说明退款后优惠券是否退回"
        }
      ]
    }
  ]
}
```

候选集生成要求：

- 问题来源使用现有离线数据集和人工补充的检索难例
- 调 retrieve 时显式设置 `rerank_options.enabled=false`
- 固定知识库范围、profile、召回参数和候选 Top20
- 保存候选文本、原始顺序、score、chunk_id、document_id 和 title
- 候选不足 20 条时保存实际数量，不补造数据
- 生成后所有重排对比都读取该文件，不再重新召回
- 数据集和报告中不得写入 API Key

`relevance` 采用人工分级标注：

| 分值 | 含义 |
|------|------|
| 3 | 包含回答问题所需的核心内容 |
| 2 | 能提供有效支撑，但单独不足以回答 |
| 1 | 主题相关，不能支撑答案 |
| 0 | 无关或容易误导 |

数据集至少包含 30～50 条有效 case，覆盖关键词精确命中、语义改写、相似干扰文档、否定条件、时间数字、多库来源和多证据问题。允许使用模型辅助预标注，但最终结果必须人工复核。

在删除旧实现前，用当前 `LLMRerankProvider` 对固定候选集运行基线，并保存：

```text
eval/opt15_rerank/rerank_llm_baseline.json
```

每个 case 正式执行至少 3 次，第一轮 warm-up 不计入时延。原始结果需包含每轮 Top5、rerank_score、latency_ms、success 和 error，不能只保存汇总值。

## 三、新增 Qwen3-Rerank Provider

新增：

```text
app/providers/rerank/qwen3.py
```

实现：

```python
class Qwen3RerankProvider(RerankProvider):
    name = "qwen3"
```

使用项目已有的 `httpx` 调用百炼兼容接口，不额外引入 DashScope SDK。

```text
POST {RERANK_BASE_URL}/reranks
Authorization: Bearer {RERANK_API_KEY}
Content-Type: application/json
```

请求体：

```json
{
  "model": "qwen3-rerank",
  "query": "用户问题",
  "documents": [
    "标题：候选标题\n正文：候选正文"
  ],
  "top_n": 5,
  "instruct": "Given a question, retrieve passages that contain evidence needed to answer the question."
}
```

请求处理要求：

- 精排候选直接使用召回结果，Provider 内部最多处理 50 条作为安全保护
- document 使用 `标题 + 正文`，Provider 内部将正文截断为 1024 字符
- 不把 vector score、BM25 score、租户信息和内部 ID 拼进 document
- `top_n = min(top_n, candidate_count)`
- chunks 为空时直接返回空列表，不调用远程接口
- 请求超时使用 `RERANK_TIMEOUT_SECONDS`
- 记录模型、候选数量和调用耗时，日志不得包含 API Key
- HTTP 非 2xx、响应非 JSON 或响应结构不合法时抛出异常，由 `RagService` 统一降级

成功响应结构：

```json
{
  "results": [
    {"index": 0, "relevance_score": 0.93},
    {"index": 2, "relevance_score": 0.34}
  ],
  "model": "qwen3-rerank",
  "usage": {"total_tokens": 79}
}
```

响应映射要求：

- 通过 `index` 找回输入列表中的原 chunk，不通过返回文本匹配
- index 必须是整数，且不能越界、重复
- `relevance_score` 必须能转换为 float，并限制在 0～1
- 按 `relevance_score` 降序返回，同分时保持原候选顺序
- 返回结果保留 chunk 原有字段，并写入 `rerank_score`
- 不使用跨请求的绝对分数阈值，分数只用于当前候选集排序

## 四、配置改造

在 `app/core/config.py` 增加：

```python
rerank_base_url: str
rerank_api_key: str = ""
rerank_model: str = "qwen3-rerank"
rerank_timeout_seconds: int = Field(default=15, ge=1)
```

其中：

- `RERANK_ENABLED` 作为全局精排开关继续保留
- `RERANK_BASE_URL` 单独配置，因为 Qwen3-Rerank 地址包含百炼 Workspace ID
- `RERANK_API_KEY` 留空时复用 `MODEL_API_KEY`，需要独立权限时才单独填写
- `RERANK_MODEL` 配置实际调用的精排模型，默认 `qwen3-rerank`
- `RERANK_TIMEOUT_SECONDS` 是高级配置，默认 15 秒
- instruct、候选安全上限和正文截断长度作为 Provider 内部常量
- 精排输出数量继续读取已有 `rerank_options.top_n`，未传时使用代码默认值 5

`.env.example` 调整为：

```env
# 专用精排：API Key 留空时复用 MODEL_API_KEY
RERANK_ENABLED=false
RERANK_BASE_URL=https://YOUR_WORKSPACE_ID.cn-beijing.maas.aliyuncs.com/compatible-api/v1
RERANK_API_KEY=
RERANK_MODEL=qwen3-rerank
# 高级配置，一般不需要调整
RERANK_TIMEOUT_SECONDS=15
```

Embedding 与 Rerank 的接口地址保持独立；同一个百炼账号下默认复用 `MODEL_API_KEY`，也允许通过 `RERANK_API_KEY` 覆盖。

删除 `RERANK_PROVIDER`、`RERANK_INSTRUCT`、`RERANK_TOP_N`、`RERANK_MAX_CANDIDATES`、`RERANK_CHUNK_MAX_CHARS` 和 `RERANK_TEMPERATURE`，并删除 `.env.example` 中关于 LLM rerank 的说明。

## 五、接入检索链路

修改 `app/services/rag_service.py`：

- `_build_rerank_provider()` 直接构建 `Qwen3RerankProvider`，不读取 Provider 类型配置
- LLM 分支仅在采集 A/B 数据期间临时保留，数据采集完成后按第八节删除
- 未开启 rerank 时继续使用 `NoopRerankProvider`
- Qwen3 调用异常时返回输入候选的原顺序 TopN，并将 `rerank_score` 设为 `None`
- 降级 metadata 中的 provider、model 和 error 必须反映 Qwen3 的实际信息，不能硬编码 `provider="llm"`
- 使用 `time.perf_counter()` 统计精排调用 `latency_ms`
- 不修改 profile 和 Plan 对 rerank 开关的现有约束

临时共存只用于命令行对比脚本，产品检索链路和前端都不提供 LLM/Qwen3 模型切换入口。

`RetrieveRerankMetadata` 增加：

Qwen3 调用成功时，metadata 至少包含：

前端不增加页面、配置项或模型选择器。原有 rerank 开关、TopN 和 `rerank_score` 展示继续使用。

## 六、实现排序对比工具

在 `pyproject.toml` 的 `eval` 依赖中增加：

```toml
"ranx>=0.3.21,<0.4",
```

新增：

```text
scripts/compare_rerankers.py
```

脚本支持：

- `prepare`：关闭 rerank，生成固定候选集
- `validate`：检查 relevance 标注、重复 chunk、空候选和 case 数量
- `run`：运行指定 Provider，保存逐 case、逐轮结果
- `ab`：在同一时间窗口交替调用 LLM 与 Qwen3，减少网络波动影响
- `compare`：计算指标并生成 JSON 和 Markdown 报告

输出：

```text
eval/opt15_rerank/rerank_llm_baseline.json
eval/opt15_rerank/rerank_qwen3_result.json
eval/opt15_rerank/rerank_llm_vs_qwen3.md
```

指标口径：

- nDCG@5：使用 0～3 的完整 relevance 等级
- MRR@5：只有 `relevance=3` 视为核心命中
- HitRate@5：只有 `relevance=3` 视为核心命中
- Recall@5：`relevance>=2` 视为有效命中
- 时延：只统计 Provider 调用，不混入 Embedding、BM25、RRF 和数据库耗时
- 稳定性：统计成功率、异常率和相同输入多次调用的 Top5 一致率
- 胜平负：按逐题 nDCG@5 的差值判断，并输出所有负向 case 的两组 Top5

报告必须包含：

- 数据集名称、case 数、候选 TopK、结果 TopN 和测试时间
- 两边实际 provider、model 和 base_url 域名，不记录 Key
- nDCG@5、MRR@5、HitRate@5、Recall@5
- P50、P95、最大时延、成功率和降级率
- 指标的原始值、绝对变化和相对变化
- 胜、平、负数量及所有负向案例
- 样本量、人工标注和远程网络波动说明

不得用跨请求的平均 `rerank_score` 判断模型质量，不得生成或填写虚构测试数据。没有可用 API Key 时，远程对比输出明确的 `SKIP`。

## 七、测试代码

```text

```

`tests/test_qwen3_rerank.py` 覆盖：

## 九、改造约束

- 不修改向量检索、BM25、RRF 和多知识库融合算法
- 不修改切块和索引数据，不执行 reindex
- 不修改 Plan、Retrieve Profile 和 rerank API 请求字段
- 不新增前端页面和模型选择入口
- 不增加 score threshold、MMR 或结果多样性处理
- 不在日志和报告中记录 API Key、Authorization Header 或用户敏感内容

## 十、验收标准

- `Qwen3RerankProvider` 单测全部通过
- 开启 rerank 时 retrieve 固定返回 Qwen3 精排结果
- metadata 显示 `provider=qwen3`、`model=qwen3-rerank` 和实际 `latency_ms`
- Qwen3 超时或响应异常时回退到原候选顺序，`degraded=true`
- 调试台原有 rerank 开关、TopN 和分数展示正常
- LLM 与 Qwen3 使用同一份固定候选完成真实对比
- 报告包含排序指标、P50/P95、稳定性、胜平负和退化案例
- 所有汇总值都能追溯到逐 case、逐轮原始结果
- 旧 `LLMRerankProvider` 和 `RERANK_TEMPERATURE` 已删除
- 原有 retrieve、多库检索和降级测试全部通过
