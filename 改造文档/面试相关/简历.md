# RAG 检索中台（rag-center）

## 项目介绍

企业级 RAG 检索中台，为多业务线提供知识库管理、文档异步索引与多策略检索的统一 API；职责边界限于证据片段召回与结构化返回，答案生成、Prompt 编排与前端交互由上游应用承接。具备多租户隔离、API Key 鉴权、三档商业套餐，以及 QPS、日检索量、知识库规模等配额管控能力。

技术栈为 FastAPI、PostgreSQL + pgvector、Elasticsearch、Celery + Redis，配套 React 调试台。检索侧覆盖普通检索与受控 Research 双入口，查询改写、词表扩展、向量与 BM25 双路并行召回、RRF 融合、多知识库全局融合、Qwen3 专业精排与可选 Evidence Pack；入库侧支持 Markdown 结构化切块、轻量文档关系索引及 Word、PDF 多格式解析；观测侧贯通 Langfuse 链路追踪、检索审计日志、用户反馈与 Golden Set 单变量消融评测，支撑检索质量持续迭代。

## 个人职责

- **整体架构与模块划分**：主导中台分层设计，从 API、Service、Repository 到 Provider 逐层拆分，划分知识管理、异步索引、检索编排、证据编排、受控 Research、多租户配额、效果评估等模块，完成技术选型与统一接口规范。
- **检索主链路落地**：打通从套餐校验、问题处理、双路并行召回到全局 RRF 融合、关系候选注入、Qwen3 精排、上下文恢复与结构化返回的完整链路，支持速度、均衡、质量、自定义四档检索策略，并与租户套餐能力做双层约束。
- **双入口检索架构**：设计普通检索与 Research 双入口，底层共用同一套召回、融合、精排与降级能力，Research 在外层增加查询分解、证据判断与补证编排；Evidence Pack 作为可选证据层独立挂载，不修改原始检索结果。
- **索引与文档引擎**：设计 Celery 异步索引流水线，覆盖解析、Section 版本化切块、轻量文档关系索引、批量向量化、向量库与搜索引擎双写；实现文档状态机、失败重试、清库重索引和全库重建脚本，并接入 Word、PDF 解析，统一产出可供切块的正文。
- **多租户与商业化配额**：实现 API Key 鉴权与哈希存储、租户级数据隔离、三档套餐的功能开关，以及 QPS、日检索量、知识库数量、并发索引数等配额限制，超限返回明确错误码。
- **可观测与效果闭环**：建设检索审计日志、Langfuse 链路追踪、用户反馈评分，并建立 Golden Set 统一评测运行器与 baseline / candidate 单变量消融流程，统一输出 Precision、Recall、P95 与模型调用数四项核心指标，支撑线上问题定位、低分 case 沉淀和调参前后对比。
- **全栈调试台**：独立开发 React + TypeScript 前端，覆盖建库、多格式上传、文档状态、检索调试、策略与多库切换、Research 链路观测、Evidence Pack 展示、套餐用量展示和结果反馈，降低业务接入成本。

## 难点与亮点

- **中台定位与多租户分级服务**：检索与生成职责分离，API Key 鉴权与三档 Plan 锁定功能开关与资源配额，Profile 独立选择速度、均衡、质量策略，Research 与 Evidence Pack 按入口与套餐分层开放，租户数据全链路隔离，超限明确报错。
- **检索全链路优化**：从向量 TopK 升级为查询改写、同义词扩展、向量与 BM25 并行召回、全局 RRF 融合、关系候选注入、Qwen3 精排与上下文恢复的完整链路，三档策略统一最终 Top5。固定评测集上准确率由约 61% 提升至 95%。
- **结构化入库夯实检索底座**：多格式文档统一解析为 Markdown 后按标题与表格边界切块，解析层与切块层解耦，双写入库并支持失败回滚与 purge 重索引；全库 reindex 后召回率由约 58% 提升至 71%。
- **检索效果可度量、可回归**：建立 Golden Set 版本管理与单变量消融流程，统一输出 Precision、Recall、P95 与模型调用数；配合检索日志、Langfuse 追踪、用户反馈与 RAGAS 评分，累计产出 20 余份可追溯实验报告，支撑混合检索、精排、图谱与 Evidence 等改造的独立验收。
- **轻量文档关系图与上下文恢复**：在结构化 Chunk 之上保留父章节、顺序邻接与显式引用关系，检索时注入关系候选并补齐上下文；相对纯 Chunk 检索，Precision 提升约 4.9 个百分点，Recall 提升约 7.5 个百分点，P95 下降约 9.1%，无额外模型调用。
- **可信证据编排**：在检索结果之上将问题拆成必要要点，为每点关联核心或辅助证据并返回完整性状态与 chunk 级引用，后端校验候选并加载原文构建，失败不影响原始检索结果；Precision 提升约 13.5 个百分点，平均上下文由约 10 条压缩至约 1.75 条，引用回溯率 100%。
- **受控 Agentic Research**：面向多要点与多跳问题，Planner 分解查询并并行复用检索内核，Decider 判断证据完整性后最多一轮定向补证，Finalizer 仅基于合法证据生成带引用答案；查询数、轮数、模型调用与超时均有硬约束，Pro 套餐显式开放，不进入默认检索档位。
- **核心链路多层降级韧性**：单路召回失败自动退化、改写与精排超时旁路、Evidence 编排失败保留原始结果、Research 异常保留已验证证据，模型或 ES 故障时主链路仍可返回可用结果。
- **六类 Provider 可插拔工程架构**：Embedding、向量库、搜索引擎、LLM、Rerank、文档解析统一抽象，工厂与环境变量切换；Rerank 线上使用 Qwen3 专业精排，分段错误码区分未授权、功能超限、配额用尽与限流，Noop Provider 表达套餐不支持而不污染业务分支。
