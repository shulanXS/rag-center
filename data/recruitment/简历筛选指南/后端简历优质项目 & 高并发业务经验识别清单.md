# 后端简历优质项目 & 高并发业务经验识别清单

> 适用：初级 ~ 高级后端简历技术初筛

---

## 1. 技术栈识别（权重 30%）

| 技术点 | 初级 | 中级 | 高级 |
|--------|------|------|------|
| 语言 | Java/Go/Python 一门 | 一门精通 | 多语言 + 选型能力 |
| 数据库 | MySQL CRUD + 索引概念 | SQL 优化 + 表设计 | 分库分表 + 一致性 |
| 缓存 | Redis 基本类型 | 缓存穿透/击穿/雪崩 | 集群 + 热点治理 |
| 消息队列 | 了解概念 | Kafka/RocketMQ 实战 | 顺序消息 + 事务消息 |
| 微服务 | — | Spring Cloud / gRPC | 治理 + 容灾 |

---

## 2. 优质项目识别（权重 40%）

### 2.1 电商 / 客服方向高分项目

| 场景 | 优质信号 |
|------|----------|
| 订单售后 | 状态机设计、幂等、补偿机制 |
| 客服工单 | SLA 计时、路由分配、升级策略 |
| 会话 / IM | 消息可靠投递、未读计数、多端同步 |
| 大促峰值 | QPS 数据、限流降级、预案复盘 |
| 搜索 | ES 索引设计、IK 分词、同步方案 |

### 2.2 项目描述质量

**高分：**

- 量化指标：日订单 XX 万、接口 P99 < 100ms、可用性 99.9%
- 个人贡献清晰：「我负责工单引擎状态机重构」
- 有故障与优化故事，非一帆风顺

**低分：**

- 仅写「使用 Spring Boot 开发后台管理系统」
- 无 QPS、无数据量、无难点

---

## 3. 高并发经验识别要点

面试前简历标注以下关键词须 **重点追问**：

- 分布式锁实现方式与踩坑
- 缓存与 DB 一致性方案
- 消息重复消费如何处理
- 慢 SQL 排查案例
- 线上故障复盘（时间线 + 根因 + 改进）

**无具体案例的高并发描述视为疑似包装。**
