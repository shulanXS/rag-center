# 转行 AI Agent 开发候选人筛选评判标准

> 适用：后端/前端/算法转 Agent、培训班转 AI、自学转行

---

## 1. 转行路径评估

| 来源 | 优势 | 需补强 |
|------|------|--------|
| 后端转 | 工程化、服务部署、API 设计 | Prompt、RAG 理论 |
| 前端转 | 产品交互、全栈联调 | Python、模型基础 |
| 算法/NLP 转 | 模型理解、评测方法 | 工程落地、业务场景 |
| 培训班转 | 框架入门快 | 真实项目、基础深度 |

---

## 2. 最低录用门槛

- Python 熟练，能独立写 FastAPI 服务
- 完成过 **完整 RAG Demo**（上传文档 → 检索 → 问答），非纯聊天
- 理解 Embedding、向量相似度、Top-K 召回基本概念
- 能阅读 LangChain / LangGraph 官方文档并动手实验
- 有 **3 个月以上** 系统学习或项目经历

---

## 3. 作品验收标准

至少满足 **4 项**：

1. 有文档 ingestion pipeline（解析、分块、入库）
2. 使用向量库或 ES 做检索
3. 接入真实 LLM API（OpenAI 兼容即可）
4. 有简单评测或 Bad Case 记录
5. 代码结构清晰（非单文件脚本）
6. README 说明架构与运行方式

---

## 4. 不建议录用

- 简历仅「ChatGPT 应用开发」无 RAG 链路
- 说不清向量检索与关键词检索区别
- 无任何可演示代码
- 对幻觉、成本、延迟无基本认知却应聘中级

---

## 5. 面试重点（转行专用）

- 为什么转 Agent？学习计划是什么？
- 讲清一个自己最熟悉的 RAG 项目每一环
- 现场设计：客服场景「用户问退款政策」的检索流程
- 基础：Python 异步、HTTP、JSON 处理

---

## 6. 录用与培养

| 表现 | 建议 |
|------|------|
| 工程背景 + RAG Demo 完整 | P4 录用，导师制 3 个月 |
| 有 NLP 理论但工程弱 | P4，加强工程培训 |
| 仅培训班模板 | 不录用 |
| 后端 P5 转 Agent | 可按 P5 定级，缩短培养期 |

入职 3 个月目标：独立维护一条 RAG pipeline，参与 Agent 功能迭代与评测。
