# 前端简历造假核验方法（框架、线上项目、工程经验）

> 适用：简历存疑或中高级候选人面试前核实  
> 原则：客观验证，避免预设立场

---

## 1. 常见造假类型

| 类型 | 表现 |
|------|------|
| 项目注水 | 仅参与却写「独立负责」「架构设计」 |
| 技术夸大 | 仅用过 React 却写「精通源码」 |
| 虚假线上项目 | 链接失效、演示站为他人作品 |
| 时间造假 | 项目周期与在职时间重叠矛盾 |
| 公司包装 | 小公司项目包装成「千万级用户」 |

---

## 2. 线上项目核验

### 2.1 链接检查

1. 要求提供 **可访问的线上地址**（测试环境需说明有效期）。
2. 打开 DevTools → Network / Sources，查看：
   - 是否有该公司域名或合理部署痕迹
   - 构建产物是否像真实业务（非纯模板站）
3. 用 **Wayback Machine** 或备案信息查询站点历史（可选）。

### 2.2 真实性追问（面试）

- 「这个页面的 XX 功能是你做的吗？当时怎么实现的？」
- 「线上出过什么 Bug？你怎么排查的？」
- 「构建部署流程是怎样的？谁负责发布？」

**红旗：** 说不出具体模块、无 Bug 故事、不了解部署流程。

---

## 3. 框架能力核验

### 3.1 React 方向

| 声称能力 | 验证问题 |
|----------|----------|
| 熟练使用 Hooks | `useEffect` 依赖数组陷阱？自定义 Hook 场景？ |
| 状态管理 | 何时用 Context vs Zustand vs Redux？ |
| 性能优化 | `memo`/`useMemo` 滥用问题？虚拟列表原理？ |
| 工程化 | Vite 与 Webpack 差异？Tree Shaking 原理？ |

### 3.2 手写 / 白板（初级）

- 实现简易 `debounce`、深拷贝（说明边界）
- 用 React 实现一个带搜索的 Todo List

**原则：** 不要求背源码，但须能讲清 **自己项目里怎么用**。

---

## 4. 工程经验核验

1. **Git：** 分支策略（Git Flow / Trunk）？冲突怎么处理？
2. **CI/CD：** 提交后自动跑什么？上线谁审批？
3. **监控：** 线上白屏怎么发现？用什么工具？
4. **协作：** Code Review 关注什么？与后端接口联调流程？

---

## 5. 第三方交叉验证

- **脉脉 / linkedin：** 核对公司与职位（仅供参考）
- **GitHub：** commit 历史、项目活跃度、代码风格
- **背调：** 中级以上核实最近一段工作经历（见背调文档）

---

## 6. 处理结论

| 结论 | 处理 |
|------|------|
| 核实一致 | 正常推进 |
| 部分夸大 | 降职级或加强笔试 |
| 严重造假 | 终止流程，标注 ATS 备注 |
