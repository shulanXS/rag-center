# Agent 简历造假核验（大模型工程、Agent 编排、微调落地）

> 适用：AI 岗位简历存疑或中高级候选人

---

## 1. 常见造假类型

| 类型 | 表现 |
|------|------|
| Demo 包装 | 仅 ChatGPT 套壳，称「自研大模型应用」 |
| 框架拼贴 | 跟着 LangChain 教程做，无法解释链路 |
| 效果夸大 | 「准确率 95%」无测试集与评估方法 |
| 微调虚构 | 写「微调 LLaMA」实际只改过 Prompt |
| 规模夸大 | 声称百万文档 RAG，实际几百条 |

---

## 2. RAG 链路核验问题

1. 文档怎么分块？chunk size 和 overlap 怎么定的？
2. Embedding 用的什么模型？维度多少？为什么选它？
3. 向量库用的什么？如何做 Hybrid Search？
4. Rerank 有没有？不用的话幻觉怎么控制？
5. 评估怎么做？测试集多少条？指标是什么？

**能画出 pipeline 图并标注自己负责模块 = 高可信度。**

---

## 3. Agent 编排核验

1. LangGraph 的 State 里存了什么？边条件怎么定义？
2. 多个 Agent 之间如何传递上下文？
3. Tool 调用失败重试策略？
4. 如何防止无限循环？
5. 线上延迟多少？成本怎么算？

---

## 4. 微调落地核验

若简历声称微调经验，追问：

| 问题 | 验证目的 |
|------|----------|
| 基座模型与参数量？ | 是否真做过 |
| 训练数据从哪来？多少条？ | 数据工程真实性 |
| LoRA rank / 学习率？ | 训练细节 |
| 评测对比：微调前后指标？ | 效果真实性 |
| 部署方式：合并权重还是 adapter？ | 工程落地 |

**答不出训练数据规模与评测对比 → 疑似仅 Prompt 调优。**

---

## 5. 作品与代码验证

- 要求演示 **本地可运行** 的 RAG / Agent 项目
- GitHub 检查：是否有评测脚本、配置文件、README 架构说明
- 中级以上：现场改一个 Prompt 或加一个简单的 Retrieval 策略

| 严重包装 | 终止 |
