# 后端简历造假核验（分布式、中间件、线上故障经验）

> 适用：中级及以上或简历夸大嫌疑候选人

---

## 1. 高频造假点

| 造假点 | 识别方法 |
|--------|----------|
| 「负责分布式架构」实为 CRUD | 追问架构图、服务拆分边界、数据一致性 |
| 中间件仅会用不会排错 | 问消费积压、重复消费、消息丢失处理 |
| 虚构 QPS / 数据量 | 要求估算：日活、峰值倍数、单机容量 |
| 线上故障经历编造 | 追问时间线、监控截图、复盘文档 |
| 分库分表未落地 | 问分片键、跨库 join、扩容方案 |

---

## 2. 分布式能力核验问题库

### 2.1 缓存（Redis）

1. 缓存穿透、击穿、雪崩分别怎么处理？你们项目用的哪种？
2. 缓存与数据库一致性：先更新 DB 还是先删缓存？
3. 分布式锁用 Redisson 还是自研？锁超时了怎么办？

### 2.2 消息队列

1. 如何保证消息不丢？生产端和消费端分别做什么？
2. 消息积压百万级怎么处理？
3. 顺序消息场景？如何实现？

### 2.3 微服务

1. 服务发现用的什么？熔断降级怎么配？
2. 分布式事务用过 Seata / 本地消息表 / Saga？选型理由？
3. 链路追踪用的 SkyWalking / Jaeger？如何定位慢请求？

---

## 3. 线上故障核验

要求候选人描述 **一次真实故障**（可脱敏）：

| 要素 | 须覆盖 |
|------|--------|
| 现象 | 用户感知、告警信息 |
| 时间线 | 发现 → 定位 → 恢复 |
| 根因 | 技术层面原因 |
| 改进 | 短期止血 + 长期预案 |

**红旗：** 只说「服务器挂了重启就好」、无任何监控与复盘。

---

## 4. 代码与实操验证

- 中级：现场 SQL 优化（给慢查询 explain）
- 中级：设计一个限流接口（令牌桶 / 滑动窗口）
- 高级：白板画客服工单状态机 + 关键 API

---

## 5. 结论处理

| 级别 | 处理 |
|------|------|
| 经验真实 | 正常推进 |
| 轻微夸大 | 降一级定级 |
| 严重虚构 | 终止，ATS 备注 |
